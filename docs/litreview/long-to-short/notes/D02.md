# D02 Wang, Golbandi, Bendersky, Metzler, Najork - Position Bias Estimation for Unbiased Learning to Rank in Personal Search (WSDM 2018, pp. 610-618)
Reading depth: sections 3, 4, 5 read from PDF text (pdftotext of cached copy from research.google PDF storage.googleapis.com/gweb-research2023-media/pubtools/4120.pdf).

- Position bias model [F, 4.1]: P(C=1|q,d,k)=P(E=1|k) P(R=1|q,d); examination depends only on position k. Simplifying assumption "a clicked document is relevant" (can be relaxed for noisy clicks, citing Joachims 2017).
- Randomisation schemes [F, 4.2]: RandTopN (shuffle top N; click counts in each position proportional to propensity) vs RandPair (swap adjacent pair k-1,k). Both applied on email search (N=3) and file-storage search (N=5); estimates agree (Fig 1), supporting the position-bias assumption. Randomisation hurts users: Table 1 reports significant MRR drops (e.g. RandTopN -13.94% / -31.04% in two table rows; per-service mapping not verified [V]).
- Estimation from regular clicks [F, 4.3]: standard EM needs repeated (q,d); proposed regression-based EM replaces the (q,d) identifier by a feature-based relevance function f(x_{q,d}) in the M step, so sparse clicks are handled; compared with an "embedded" discriminative GBDT with one-hot position features (split depth 1).
- Data [F, 5.1]: email and file-storage search logs, at most one click per query (overlay UI), queries without clicks discarded. Metric: weighted MRR using RandPair inverse propensity as ground truth.
- Results [F, 5.2]: EM and Embedded comparable in log-likelihood; EM propensity yields better ranking; RandPairCorrected vs NoCorrection +2.14% (email), +0.15% (file storage); EMCorrected also significantly better than NoCorrection; EM converges in ~10 iterations; DocLevel/QueryLevel IPW approximations for pointwise models did not beat baseline while the EM relevance component did.
- Code/licence: not released [V]; proprietary logs.
- For us [I]: shows how to get a position curve without intervention when content features are informative: heat(t) ~ position(t) x content-score(x_t). The identifiability depends on content features being shared across positions.
