# B05 How Should Video LLMs Output Time? (arXiv 2604.08966)
读取深度：sections（arxiv.org/html：1 引言、3 范式形式化、4 实验设置、5 结果）。
- 三范式：Text Numeral（VTimeLLM 式，时间当文本）、Temporal Token Generation（TRACE 式，独立 tokenizer，事件=(时间,显著度,caption)）、Continuous Temporal Decoding（DisTime 式，<TIME_STAMP> 隐状态经 MLP 解码为 reg_max+1=33 bins 上的分布，1D-IoU + DFL 损失）。[F]
- 控制变量：SmolVLM2-0.5B/2.2B、FastVLM-1.5B、Molmo2-4B/8B；冻结视觉编码器，LoRA(r=16)，1 epoch，32 帧；Charades-STA（~30s）、QVHighlights（~150s）、YouCook2。[F]
- 结果（文本给出的数字）：Charades-STA 上 Continuous 0.5B mIoU 43.4 > Text 8B mIoU 27.5；FastVLM-1.5B Continuous R1@0.5=51.3，高于已发表 7B 的 TRACE 40.3 与 Grounded-VidLLM 36.4；仅用 25% 训练数据 Continuous 达 40.2 mIoU，高于用 100% 数据的 Text (20.8) 与 Gen. (28.1)；Text 范式在 64 帧时退化到 20.5 mIoU；延迟：Continuous 794 ms/query(2.2B)，Text 与 Gen. 更慢。[F]
- 限制：只比较输出头/表示；三者都输出自由连续时间，没有"对候选切点分类/排序"的臂；backbone ≤8B，数据集偏短视频。[F]
- 作者自述：Gen. 范式在严格边界精度上落后，但独有 saliency 头；所有范式在多步因果 query 上都失败（IoU 低）。[F]
