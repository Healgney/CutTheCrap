# C16 QaDecontext: A Question Answering Framework for Decontextualizing User-facing Snippets from Scientific Documents (Newman, Soldaini, Fok, Cohan, Lo; EMNLP 2023; arXiv 2305.14772)
reading_depth: sections 1-6 via ar5iv (last ~7k chars unread)

- [F] Task: rewrite a snippet shown outside its document so it is understandable alone, preserving meaning; snippets need context for terms defined earlier, pronouns whose referents lie in other paragraphs, assumed background. User-facing requirements: multi-sentence snippets, preserve sentence count/roles, make edits visible (bracketed).
- [F] Scientific text is harder: only ~20% of snippets decontextualizable from their own paragraph (~50% with abstract) vs 80-90% for Wikipedia (S2.2, Table 5).
- [F] Three-step framework: question generation -> question answering over source document -> rewriting. QaDecontext prompting strategy.
- [F] Data: 289 snippets, 487 questions/answers; sources S2ORC citation contexts and Qasper supporting passages; questions by domain experts (Upwork), answers and rewrites via Prolific.
- [F] Human eval on 60 snippets; two coauthors, 70% binary agreement on 30 overlapping: QaDecontext convincing in 38% vs 33% end-to-end (p=0.57, n.s.); only 42% of gold decontextualizations judged acceptable. SARI-add: gpt-4 end-to-end 0.103, davinci 0.135, QaDecontext 0.146; oracle QA up to 0.527; question answering is the bottleneck.
- [F] Code github.com/bnewm0609/qa-decontext (license not stated in text read).
- [I] Shows the required amount of context is domain dependent and that even gold rewrites are low-agreement; relevant to how we should validate any self-containedness label for podcasts (expect low agreement).
