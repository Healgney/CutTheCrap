## 1) Task definition
- [F] Transcript-based rough-cut generation for speech-centric videos (interviews, lectures, meetings, podcasts-like): input = time-aligned sentence transcript (with optional diarization and an optional editor focus/query) and a target duration/retention budget; output = strictly extractive, sentence-aligned spans in source order, shown as colour-coded (green/yellow/red) timeline markers with confidence, then assembled into a cut (user study target: 60 s from 5-6 min videos). Not a K-clip or standalone-clip problem; the output is one concatenated summary (multiple spans).

## 2) Label source and construction
- [F] No training. Evaluation uses MeetingBank (6,892 city-council segments with human extractive reference summaries) and MeetingBank-QA (three curated fact questions per meeting, answered by GPT-4.1 nano from the extract alone, exact match). User study: 11 experienced editors, 3 speech-centric videos of ~5-6 min.
- [I] The reference is a text-summary reference from public meetings, not a clip-quality or engagement label; no behaviour data.

## 3) How start/end are determined
- [F] Candidate units = transcript sentences with timecodes; spans are runs of contiguous (or <=2 s gap) sentences; the selector snaps clip boundaries to sentence limits ("timecode fidelity" = fraction of boundaries coinciding with sentence timecodes; 100% by construction), preserves source order, and keeps duration within a 2% overshoot bound. Selection is the choice among sentence candidates under a budget (candidate-set formulation, deterministic budgeted selector). Boundary quality vs human boundaries is not evaluated.

## 4) Self-containedness / context completeness
- [F] Partially addressed: Stage 1 (overview/coverage), Stage 2 induces a global RULE_OBJECT (intent, keywords, speaker roles; "Include opening and closing framing" appears in an example rule) so small windows (50 sentences) are ranked with global context; "yellow" markers extend context as the budget allows; source order is preserved "for coherence". The related-work claim is that plain extractive summaries "disrupt temporal consistency and fail to preserve narrative flow". There is no metric of understandability or dangling references; the Coherence rating in the user study is a 5-point self-report.

## 5) Evaluation and key numbers
- [F] Table 1 (MeetingBank, comparable lengths; R-1/R-2/R-L/BLEU/METEOR/avg sentences): Oracle 61.8/46.6/52.6/23.0/52.4/64.9; Lead-3 28.1/19.5/25.8/7.9/23.5/40.8; LexRank 24.6/10.7/19.1/5.9/17.7/53.7; TextRank 30.3/16.0/24.4/9.2/22.1/61.8; single-prompt 41.4/21.4/30.6/11.1/31.5/52.1; three-stage 43.1/21.7/31.1/11.4/32.8/56.2. Note the three-stage variant retains ~4 more sentences than single-prompt (56.2 vs 52.1), so the length match is only approximate.
- [F] MeetingBank-QA exact-match: three-stage above single-prompt at retention 0.05-0.50 and converges near full retention (Fig. 7; values not extracted).
- [F] Rough-cut properties: duration error <=2%, source order preserved, boundaries sentence-aligned (by construction).
- [F] User study: 11 professional editors, within-subjects, 3 workflows (manual, opaque auto rough cut, marker-based), 15 min per 60-s cut; 5-point ratings: marker system trust median 3 [2.5-4.5] vs auto 3 [3-4]; control 4 [4-5] vs 4 [3-4]; efficiency/satisfaction higher than manual and opaque auto per abstract; quality ratings similar across workflows; 6/11 chose manual for most control. Statistical tests not extracted.

## 8) Self-stated limitations (Sec 7.4)
- [F] Single model (GPT-4.1 nano) for generation and QA evaluation (possible bias); transcript-first (no audio/visual signals); no personalisation; evaluation limited to long speech-centric content (lectures/podcasts/panels may need schema extensions); small human study.

## 9) Difference from our direction
- Shares: speech-only input, sentence-level candidate units, sentence-snapped boundaries by construction, duration-budgeted selection, LLM ranking over windows with a global rule to cope with long context (a ready text-only baseline recipe for our pipeline, RQ3/RQ4).
- Differences: summarisation objective (information retention on MeetingBank, not engagement or publishability); output is a merged summary across the whole video (not independent 15-90 s clips); "coherence" only user-rated; no self-containedness constraint per clip; no hook title; no behaviour or published-clip labels; no boundary metric against human cuts. Threat to novelty: low-medium for the text-only selector component; higher as a baseline to beat.
