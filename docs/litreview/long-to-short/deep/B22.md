# B22 Timeline-Bench (arXiv 2609.35143 v1; Gupta, Arora, Tankala; preprint under review) — 深读记录
读取方式：arxiv.org/html/2609.35143v1 全文文本（Sec 1–9，App A–N 的相关部分）。reading_depth = full-text（附录 H–L 的 agent 配置/命令失败分析仅略读）。

## 1) 任务定义
- 56 个真实剪辑任务：给定 brief、原始素材、Docker 环境与时间限制，agent 需检视素材、选段排序、配音画协调并渲染成片；评测只看最终视频，允许不同合理剪法（Sec 1–2）。[F]
- 与我们不同：是 agent 端到端剪成片，不是"从长视频选 K 个 clip"。[F]

## 2) 参考答案/标签来源与构造
- 56 个任务来源：11 个购买的 EditStock 工程包、15 个公开的 Cinestudy 项目、30 个向专业剪辑机构委托的新项目；每个任务有专业 reference edit（Cinestudy 的参考由专业剪辑师从公开提交中挑选）（Sec 2.1）。[F]
- 约 33.0 小时主素材；单任务源时长 2.3–240.4 分钟（中位 12.4）；成片窗口 25–315 秒；41 横屏 + 15 竖屏（Sec 2.3）。[F]
- 验证：专业剪辑师核对 56 个任务的 brief/素材/参考一致性；每任务提供"机械 oracle"（低工艺但满足交付规格）验证交付测试；内容与 brief 测试在 reference 上验证；用单缺陷对照（静音、黑屏开头、乱序、冻结画面）验证测试能拒绝缺陷输出（Sec 2.2）。[F]
- 人类偏好研究：43 名自由职业剪辑师（计时付费，与答案无关），平均至少 2 年专业经验（4 人<1 年、27 人 1–3 年、8 人 4–7 年、4 人≥8 年，App F）；每对 3 人、863 对→2589 判断（2582 有效）；不给 brief，只给一行"受众与目的"；两个视频须完整播放后才可作答（Sec 3.2）。[F]

## 3) 起止点如何预测或选择；边界精度
- 无时间戳边界预测概念；agent 用 FFmpeg/Python/Remotion 等工具自行剪。素材"视觉靠静帧/contact sheet（83% 的原生读取），听觉靠转写与电平测量"（Sec 6）。边界精度/容差：不适用。[F]
- 间接相关：quality test 的输入含"每分钟剪辑数（用 PySceneDetect 自适应检测器的复现）"等度量；发现 agent 的剪辑速度只有 reference 的 0.72×（Sec 6, Fig 5b）。[F]

## 4) 多解评测处理
- 设计目的：协议"容纳多个有效编辑方案"（Sec 1）：tests 判是否满足明确要求，quality test 判相对 reference 是否不差。[F]
- Quality test（Sec 3.3, App D）—"editor-calibrated judge"的具体校准：
  1. 三个跨厂商 MLLM judge（Gemini 3.8 Flash 看带声音的视频；GPT-6 Astra、Claude Opus 5.5 读 1fps contact sheet + 4 项文件度量：每分钟剪辑数、最长静止画面、EBU R128 响度、静音占比）；单独给 agent edit 与 reference 打分（互不可见）；拿到人类研究使用的书面 rubric；不看 brief。[F]
  2. 每 judge 对 overall 与 5 维（story&assembly、pacing、picture、sound、graphics）打 1–10 整数分，另输出至多 5 个带时间戳的缺陷与一个 acceptability 是/否；judge 分=overall均值+0.2×五维均值（缺陷与 acceptability 不入分）；Gemini 2 次 pass、其余按设置取均值（App D.1–D.2）。[F]
  3. 各 judge 以其在 919 个视频（863 agent edit + 56 reference）上的均值/标准差做 z-score，常数冻结供新提交；面板分=三 z 平均。[F]
  4. 通过条件：agent 面板分 − reference 面板分 ≥ collection 的平局边距。边距=在该 collection 的研究对上取"最小观测 gap x，使 gap≥x 的对占比不超过人类 win-or-tie 率"（App D.3）。冻结边距：Cinestudy 0.30、Commercial 0.52、EditStock 0.21、UGC 1.54（以 judge SD 计，1 SD≈1.0–1.5 分）；报告结果用 leave-one-agent-out 重拟合，与冻结值相差 ≤0.09（Sec 3.3）。[F]
- 与人类一致性的数字（均 [F]）：
  - 系统层面（16 agent，边距 leave-one-agent-out）：resolution rate 与人类 win-or-tie 率 Spearman ρ=0.93、Pearson r=0.93，平均差 3.0 点、最大差 7.2 点（Gemini 3.1 Pro Preview）（Sec 5）。
  - 单 edit 层面：面板与人类多数票 κ=0.15，一个人类与其余人多数票 κ=0.14；每任务通过率与人类每任务 win-or-tie 率 ρ=0.32（App D.4）。→ "valid per agent, not per edit"。
  - 人类自身可靠性：单判断 Krippendorff α=0.103（序数）；agent 层 win-or-tie 率的 Spearman–Brown 可靠性 0.84（3 人/对，由单判断可靠性 0.632 推得）；逐个剔除剪辑师排序 Spearman ≥0.964；A/B 顺序效应 -1.2 点（CI -3.7…1.1）（App F, G.1）。
  - 排序对边距不敏感：全体边距降低 0.1 SD 会多解决 27 个 run，但排序 Spearman 0.96（Sec 6）。
- 自述局限：校准与验证使用同一批人类票；每 agent 每任务只跑一次；reference 不是"certified ground truth"（Sec 7）。[F]
- 参考的统计位置：human 偏好 reference 83.5%（agent 11.1%，无偏好 5.5%）。[F]

## 5) 评测指标与关键数字
- 主指标：task resolution rate（通过全部测试的任务占比）+ 人类 win-or-tie 率（GDPval 式，先任务内平均再跨任务平均）。16 agent；896 run；最佳 GPT-6 Astra+Codex+curated guidance 15/56=26.8%（Sec 5，Table 1）；平均 14.0%（125/896，CI 11.7–16.4）；人类 win-or-tie 平均 16.5%，4.0%–24.4%。[F]
- 失败分布：771 个未解决 run 中 562（73%）只败在 quality test（Fig 4a）；中位失败差 0.82 judge SD；35 个任务无 agent 解决；Rasch 模型：任务难度变化是 agent 能力变化的 2.6 倍；Cinestudy win-or-tie 28.7% vs UGC 6.8%（Sec 6）。[F]
- 成本：已记录成本的 12 个 agent 每 run $0.13–$41.27，成本与解决数 ρ=0.79；最佳 agent 估约 $9.76/run。[F]
- 同一 harness 下 10 个模型 + 4 个模型在原生 harness + curated guidance + computer-use 共 16 个 agent（Sec 4）。[F]

## 6) 模态消融
- 没有系统的模态消融；唯一接近的对比是"curated editorial guidance"（1,909 字通用建议）与"computer use"（仅屏幕+鼠标键盘，DaVinci Resolve）条件（Sec 4.1, App I）；computer-use 的所需台词漏掉率 41.5% vs 转写 agent 5.9%（Sec 6 Table 2）。这是 harness/工具消融，不是音频/视觉模态消融。[F]
- Gemini 3.8 Flash 看带声音的视频，其余 judge 看静帧+度量：judge 之间的模态差异未做单独消融。[F]

## 7) 数据/代码/许可（App M，原文）
- 代码、任务定义、rubric、冻结常数与 Timeline-Bench 1.0 结果以 Apache-2.0 发布；人类研究以聚合统计与每 run 票数发布。[F]
- 源素材只对获批研究团队开放，禁止再分发输入/输出/截帧/片段，禁止用于训练生成模型或在基准上训练/调参，禁止识别/画像出镜人物。[F]

## 8) 论文自述局限
- 见 4) 末；另：只对 56 个任务和被采样 agent 作结论，不代表剪辑师能力（Sec 1 末）。[F]

## 9) 与我们方向的具体差异
- 它评 agent 的全片剪辑质量，不评"选哪些时间段"；无边界精度、无自包含、无 hook 标题；素材含大量画面类/商业类，不是语音为主的长对话。[I]
- 可借鉴：(i) 用"边距=使通过率逼近人类 win-or-tie 率"的方式把 LLM judge 分差映射到人类偏好；(ii) leave-one-agent-out 防循环；(iii) 必须同时报告单判断 α/κ 与系统层相关，避免把系统级 ρ=0.93 误读成单 clip 可用。[I]
- 对新颖性的影响：其"人类校准 judge"协议可作为我们 judge 部分的方法对标；它也明示 judge 只适用于排序系统，因此若我们要对单个 clip 打分/用作 reward，缺乏文献支持，需要自己的人类验证（对新颖性有利）。[I]
