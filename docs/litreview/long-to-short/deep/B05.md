# B05 How Should Video LLMs Output Time? An Analysis of Efficient Temporal Grounding Paradigms (arXiv 2604.08966) — 深读记录
读取方式：arxiv.org/html/2604.08966 全文文本（Sec 1–6，Table 2–4，Fig 2–4 文字；附录 Table S1/S3/S5/S6 仅略读）。reading_depth = full-text（附录略读）。

## 1) 任务定义
- Video temporal grounding：视频 + 文本指令 → 时间段（moment retrieval）、显著度（highlight detection）、或带时间的多事件（dense video captioning）。研究问题：输出"时间"的方式（输出范式）对精度和效率的影响，且把 backbone、数据、训练协议固定（Sec 1）。[F]

## 2) 标签/参考答案来源与构造
- 训练集：约 120 万带时间标注的样本，约 40 万个独立视频，11 个来源；moment retrieval 66.8%、grounded VideoQA 21.5%、dense captioning 11.6%；三种范式共享同一批 (video, query, annotation)，各自套自己的格式（Sec 4.1，细节在附录 Table S1/S3）。[F]
- 评测：Charades-STA（~30 s）、QVHighlights（~150 s，有 moment 与 frame 级 saliency）、YouCook2（~320 s，dense captioning）；沿用公开标注，未做重标注。[F]

## 3) 起止点如何预测或选择；边界精度与容差
- 三范式（Sec 3）：
  - Text Numeral（VTimeLLM 式，但改成绝对秒数，例如 "from 52.0 to 63.0 seconds"，纯 next-token CE）；
  - Temporal Token Generation（TRACE 式：事件=(时间,显著度,caption)，时间/分数由独立 tokenizer 与词表（数字、分隔符、同步符）和各自的 tower/head 处理）；
  - Continuous Temporal Decoding（DisTime 式：一个 <TIME_STAMP> token 的隐状态经 3 层 MLP 解码成 reg_max+1=33 个 bin 上的起/止分布，用期望得到连续值；损失=1D-IoU + distribution focal loss）。
  [F]
- 配置：冻结视觉编码器 + LoRA(r=16, α=32)，1 epoch，lr 1e-4，32 帧均匀采样；Time Decoder/Encoder 为 3 层 MLP；3 个随机种子在 SmolVLM2-2.2B 与 Molmo2-4B 上标准差 ≤0.5 mIoU（Table S5）。[F]
- 重要混杂因素 [I]：Continuous 臂使用 IoU 类损失 + DFL，Text 臂只有 CE，二者"输出接口"与"是否直接优化 IoU"同时改变；结论是"这一整套配方"而非纯接口效应。bin 位于归一化时间轴，33 bins 对长视频粒度很粗（期望可给出连续值，但无证据说明长视频下的精度）。
- 边界精度度量：R1@0.5、R1@0.7、mIoU；无 IoU≥0.9、无秒级误差、无容差窗口 F1。[F]
- "回归 vs 候选切点"：三臂均为自由连续/文本时间，无候选切点分类/排序的臂；作者的结论里开放问题只列了输入侧时间编码与显著度分支，没有提候选选择。[F]

## 8) 论文自述局限（Sec 6 + 5.4）
- 固定了输入侧时间编码，未研究其与输出范式的交互；Continuous 范式缺少原生显著度打分；所有范式在多步因果 query 上失败，需输入侧视频编码创新。backbone 仅 0.5B–8B 紧凑模型。[F]

## 9) 与我们方向的具体差异
- 它：短视频（30–320 s）、query 条件、画面-only、紧凑模型、三种"生成连续时间"的对比。我们要的"在句末/轮次/镜头切候选上选择 + 精修"完全不在其设计空间内。[I]
- 对"回归 vs 候选切点选择"最终判断：本文是目前找到的最接近"受控输出范式消融"的工作，但没有候选选择臂（Table 2 三个范式 Text/Cont./Gen. 均输出自由时间）。结论：直接证据"未找到"。[F]
- 可借鉴：分布式（bin+期望）输出对含糊边界更稳（单例）与数据效率结论，可作为"候选内微调"的参考；不能直接外推到小时级语音视频。[I]
