# B03 Time-R1 (Wang, Wang, Xu et al.; arXiv 2503.13377 v3; NeurIPS 2025) — 深读记录
读取方式：arxiv.org/html/2503.13377v3 文本（Sec 1–5，Table 1–2，Fig 3–5 文字，App A/B）。reading_depth = full-text（Sec 2 相关工作与附录 baseline 细节略读）。

## 1) 任务定义
- Temporal video grounding：长视频帧序列 + 语言 query → 最匹配的时间边界 [t_s,t_e]，t∈R+（Sec 3 起首）。模型先生成 <think>…</think> 推理再给 <answer>t_s to t_e</answer>。[F]

## 2) 标签/参考答案来源与构造
- TimeRFT 训练集：来自 YT-Temporal、DiDeMo、QuerYD、InternVid、HowTo100M 的视频，grounding 标注来自 VTG-IT、TimeIT、TimePro、HTStep、LongVid，合计 339K 样本；用基座模型的 IoU 作难度，按以 IoU=0.3 为中心、方差 0.2 的高斯采样得到 2.5K 中等难度样本做 RL（Sec 3.3, App B）。[F] 标签是沿用已有数据集标注，未重新标注，也未审计标注噪声。
- TVGBench（Sec 3.4）：从 Charades-STA、ActivityNet-Captions、HiREST、EgoNLQ、TaCoS 平衡抽取 800 个实例，时长从短片到 3 分钟，query 中心近似均匀分布，11 类 query 语义由 DeepSeek-V3 标注并近似平衡（HAS 偏多）。[F]

## 3) 起止点如何预测或选择；边界精度与容差
- 文本形式输出连续时间；GRPO（G=8，β=0.04，token 级损失，全量微调 LLM、冻结视觉编码器；2 FPS，约 2.8M 像素/视频；RL 阶段 5 epoch，batch 8）（Sec 4.1, App B）。[F]
- reward：r = r_tIoU + r_form。r_tIoU = IoU·(1−|t_s−t_s'|/t)·(1−|t_e−t_e'|/t)，即在 IoU 上乘以端点偏差占视频时长的惩罚；动机是真值覆盖整段视频时，宽松预测 IoU 也很高（例 GT=[0,30]，预测 [10,25] 的 IoU 0.5 → tIoU 0.28）。r_form 为模板格式 0/1（Eq.3–6）。[F]
- 对容差的论述（Sec 3.2）：优化 IoU 自然鼓励预测落在允许误差 ε 内即可获得高 IoU，使模型关注语义而非 SFT 式的精确数值对齐；tIoU 作为"更严格、更有信息量"的纠偏。[F]
- 与"回归 vs 候选切点"：只有自由生成的连续时间；无候选选择。[F]
- Table 2 消融（Time-R1-7B，TVGBench，R1@0.3/0.5/0.7）：行1 基线（无 tIoU、GF、ME、SF）38.0/24.8/13.2；行2 仅 tIoU 36.0/23.6/12.9；行3 仅 GF 37.2/25.0/13.4；行4 仅 ME 39.9/26.0/14.2；行5 tIoU+GF 38.4/25.6/14.1；行6 tIoU+ME 39.4/26.5/16.4；行7 tIoU+GF+ME 41.6/28.5/15.6；行8 全部（含逐 epoch 样本过滤）41.8/29.4/16.4。→ 单独的 tIoU 并不提高（R1@0.7 12.9 vs 13.2），与多 epoch 结合才在 R1@0.7 上 +2.2（14.2→16.4）；tIoU 的收益与其它配方强耦合，不能当作"边界惩罚单独有效"的证据。[F]（此行列对应由表头顺序 tIoU/GF/ME/SF 推出，部分行用正文交叉核对：row1→row4 的 13.2→14.2 与正文一致。）

## 4) 多解评测处理
- 单真值段，R1@m 与 mIoU；无多参考、无集合召回、无 judge。[F]

## 5) 评测指标与关键数字（Table 1，R1@0.3/0.5/0.7）
- Time-R1 (7B，仅 2.5K RL 样本，零样本)：Charades-STA 78.1/60.8/35.3；ActivityNet 58.6/39.0/21.4；TVGBench 41.8/29.4/16.4。Time-R1*（在下游数据上微调）：Charades 82.8/72.2/50.1；ActivityNet 73.3/55.6/34.0。正文对比：Charades R1@0.7 35.3 vs VideoChat-Flash 27.6、TimeSuite 24.0；ANet 21.4 vs VTimeLLM 14.3、TimeChat 10.7；TVGBench 16.4 vs TRACE 14.6、Gemini-2.5-Pro 12.8。[F]
- RL vs SFT（Fig 4）：ActivityNet mIoU RL 16.3→29.2，SFT 降到 15.4，SFT-LoRA 25.9；VideoMME 长视频 QA RL 53.0→54.2，SFT-LoRA 降至 51.7。[F]
- 注意：这些数字在 TimeLens 的重标注基准上被重新评估，Time-R1-7B 仅 36.6/33.1/49.2 mIoU（TimeLens Table 1），说明原基准分数受标注噪声影响。[F，跨论文]

## 8) 论文自述局限（App A）
- 训练与推理慢（模型大、自回归文本生成）；为省显存采用低帧率，可能丢失细粒度运动；目前不能处理超长视频（如整部电影）。[F]

## 9) 与我们方向的具体差异
- 它：query 条件的单段定位，视频至多数分钟（TVGBench ≤3 分钟），无语音。我们：小时级语音视频、无 query、K 个 clip。[I]
- 价值：是"IoU/tIoU 作 verifiable reward + 难度采样 + 多 epoch"配方的源头；其 tIoU 额外端点惩罚是少数把"端点精度"写进 reward 的设计，可作为我们边界精修 reward 的起点，但消融显示其收益耦合于训练策略。[I]
- 对新颖性的影响：没有候选切点、没有多解、没有边界对齐到语言单元，不影响我们的核心主张；其局限（超长视频不可用）正是我们的场景缺口。[I]
