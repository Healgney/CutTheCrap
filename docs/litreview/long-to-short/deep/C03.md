# C03 Transforming Podcast Preview Generation: From Expert Models to LLM-Based Systems
Zhu, Clifton, Ghazimatin, Tanaka, Ronan. ACL 2025 Industry Track (9 pages, per arXiv comment). arXiv 2505.23908 (v2, 3 Jun 2025). Read: full HTML text (Sections 1-7, Appendix A), two passes, plus own grep of the HTML text. reading_depth = full-text.

## 1) Task definition
- [F] Generate a short preview of a podcast episode (episodes can exceed one hour) so a listener can decide whether to listen. A preview is a contiguous span of the transcript (not newly generated text), about one minute.
- [F] Input to the LLM (Gemini 1.5 Pro): sentencized transcript with a start and end time in seconds per sentence, plus episode title and description; few-shot examples; a prompt with structured reasoning steps. Output: start and end timestamps of the chosen span.
- [F] The framing sentence of the paper (Introduction) says previews are short representative segments that capture engaging, self-contained moments that are easy to understand without additional context, and attributes this principle to Barua et al. 2025 (Lotus, arXiv 2502.07096). Section 2 (Previous Work) also says previews must "serve as standalone content", which it uses to distinguish the task from highlight extraction and from topic-segment-based methods.

## 2) Labels / annotation source and agreement
- [F] There are no training labels. The LLM is prompted; few-shot examples are manually curated previews; prompt iteration used a small evaluation set of episodes from diverse categories with feedback from product and design teams (Section 3).
- [F] Offline human evaluation (Section 4.1): about 20 internal evaluators; each assessed about 20 episodes (varied with availability). 238 valid episode annotations. The text does not give the number of unique episodes, the number of raw annotations, or why some were discarded, and does not say whether an episode received more than one annotation.
- [F] Inter-annotator agreement: none reported (no kappa, alpha or percentage agreement anywhere in the text).
- [F] Raters saw episode title, description and show name; listened to both previews with subtitles; the two previews were randomly ordered to reduce position bias. Whether they had the full transcript is not stated.

## 3) How self-containedness / understandability without context is defined and measured
- [F] No formal definition and no automatic metric. It is operationalized only as human Yes/No questions (Section 4.1, Table 1), asked per preview:
  - Q1 "Understandability": "Does the preview help you decide if this episode is relevant for you?" (note: this wording is about decision usefulness, not about the clip being interpretable on its own).
  - Q2 "Contextual clarity": "Does the preview plus metadata contain enough context to understand what is being talked about from the preview?" (this is the item closest to self-containedness, and it explicitly allows the title/description metadata to supply context).
  - Q3 "Interest level": "Does the preview show an interesting part of the episode?"
  - Plus a pairwise item "Which preview is better?" (Preview 1 / Preview 2 / tie).
- [F] Scale: binary Yes/No per question; ternary for preference.
- [F] Correlation with other human measures or with any automatic proxy: not reported.
- [F] Enforcement inside the generator is by prompt: the paper's summary of prompt requirements says a preview should start and conclude with complete thoughts, begin with an engaging introduction, progress from foundational concepts to detailed insights, exclude ads, be about one minute, align with the episode theme. Full prompt text is not given (Appendix A is only a mock transcript format).
- [I] Because self-containedness is instructed in the prompt and then judged by a single binary item that accepts metadata as context, the paper cannot separate "stands alone" from "stands alone given title+description".

## 4) Start/end determination and unit
- [F] Unit = sentence. Transcripts are sentencized with punctuation heuristics; each sentence has start/end seconds (Appendix A).
- [F] The LLM chooses start and end; post-processing trims to the last complete sentence that starts within one minute (Section 3.3); the paper says the trimming is driven mainly by product requirements.
- [F] Legacy system: an in-house audio-based sentence-break detector proposes boundaries, a trimmer model uses sentence breaks and selectivity scores to adjust candidate start/end for coherence within one minute; ad and non-speech segments are down-weighted; topic/speaker boundary and question-answer segment analysis are used "to ensure smooth transition of topics" (Section 3.1/3.2).
- [F] Average lengths: about 62 s (LLM) vs about 56 s (legacy).
- [F] No evaluation of boundary accuracy (no human boundary-rating item, no IoU).

## 5) Metrics and key numbers
- [F] Table 2 (Section 5.1): proportion z-test per question: Q1 z=-4.05 (p=5.09e-5), Q2 z=-3.40 (p=6.7e-4), Q3 z=-4.32 (p=1.59e-5); all significant in favour of the LLM. The text names statsmodels proportions_ztest but does not state the null, sidedness, or which proportions are compared; per-question Yes percentages are not reported.
- [F] Pairwise: "better than or non-inferior" 81.09%, "better" 54.2%, binomial p=1.37e-10 (238 annotations). Implied counts [I, derived]: about 129 wins, 64 ties, 45 losses. Non-inferiority is not formally defined.
- [F] Latency: about 100 s per episode (legacy) vs under 20 s (LLM), "5x" (Section 3.4).
- [F] Online A/B (Sections 4.2, 5.2): 6 weeks, 67 English-speaking countries, even split. LLM previews were generated for a subset (34% of episodes seen); the rest used legacy previews in both arms. Reported: +4.6% "podcast evaluation time per user" in week 2 and +4% "evaluation time per preview" in week 2. The abstract calls the 4.6% "user engagement with preview content"; Section 5.2 defines it as evaluation time, and "engagement" is never defined. No sample sizes, test statistics or p-values for the A/B test.

## 6) Modality ablation (audio vs transcript)
- [F] The LLM system is text-only; the legacy system uses audio signals (language ID, sound-event detection, sentence-break detection, ad detection, plus other expert models). The text-only LLM was preferred or tied 81.09% of the time.
- [I] This is not an ablation: system, prompt, and ranking logic all differ. It shows only that a text-only LLM can match or beat an audio-augmented feature-engineered pipeline for this task. No laughter or prosody analysis.

## 7) Data / code / license
- [F] No dataset or code release statement. Proprietary Spotify data. arXiv page license shown: CC BY-NC-ND 4.0 (paper only). Ethics Statement covers creator opt-out and multilingual adaptability.

## 8) Limitations stated by the authors
- [F] There is no limitations section. Scattered constraints: prompt tuning on a small internal evaluation set; language filtering relies on noisy metadata; coverage of the A/B test only 34% of episodes.

## 9) Differences from our direction (long speech video to K standalone clips with aligned boundaries and a hook title)
- Output: one preview per episode, not K ranked clips; no hook title is generated (the pairwise task does not evaluate titles).
- Self-containedness: a prompt constraint plus one binary human item that allows metadata as context; no decomposition (dangling reference / missing setup / unanswered question / joke without setup), no agreement numbers, no automatic score.
- Supervision: none; no behavioural labels (replays, clicks) used for training; the only behavioural signal is the A/B test on preview evaluation time.
- Boundaries: sentence-level by construction, not evaluated.
- Modalities: text only; no frames, no laughter, no speaker turns used by the LLM.
- Domain: audio podcasts previews for discovery (browse/ search), not short-form social clips.
- Threat to novelty (RQ1): the idea of choosing a "self-contained" ~1-minute sentence-aligned span with an LLM is already published and deployed; novelty has to rest on a validated, decomposed, independent self-containedness measure, K-ranked output, behavioural supervision, and boundary precision.
