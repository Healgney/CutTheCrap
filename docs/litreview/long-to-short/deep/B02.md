# B02 TimeLens (arXiv 2512.14698 v2, CVPR 2026) — 深读记录
读取方式：arxiv.org/html/2512.14698v2 全文文本（Sec 1–6，App B/C/D/E/F/H，Table 1–5）。reading_depth = full-text（App G 标注界面与手册、App I 其它模型对比略读）。

## 1) 任务定义
- 视频 v + 文本 query q → 单个时间段 S=(t_start,t_end)；每个视频可有多对 (q_i,S_i)（Sec 3.1）。评测是 top-1 预测与单一真值段的 IoU。[F]
- 研究范围：数据质量诊断 + 算法设计（时间戳编码、训练范式、RLVR 配方）。[F]

## 2) 标签/参考答案来源与构造
- 标注准则：输入侧 4 条——query 清晰具体、事件确实存在、query 唯一（Charades-STA 重复 query 严重）、避免信息泄漏（如 "ending credits" 泄露时间位置）；输出侧 2 条——annotation precision（边界应精确，排除不符描述的子段）、annotation exhaustiveness（段外无其它满足 query 的片段）（Sec 3.1）。[F]
- 人工 diagnose-then-refine：同一标注员既查错又修正；不向标注员展示原时间段；同一视频的 query 成组检查唯一性；每批次由另一标注员交叉验证，错误率超阈值整批退回；试标十余家供应商后择优，配手册和培训（Sec 3.2）。[F] 标注者人数、一致性数字未给出 [F: 未报告]。
- TimeLens-Bench（Table 4）：Charades-TimeLens 1,313 视频/29.6s 均长/3,363 标注（原 Charades-STA 对照），ActivityNet-TimeLens 1,455 视频/134.9s/4,500，QVHighlights-TimeLens 1,511 视频/149.6s/1,541；合计 4,279 视频、均长 107.8s、9,404 标注。处理方式：高质量 query 只精修时间段，低质量 query 改写或重写，不可修复的丢弃。[F]
- 错误统计（Sec 3.3, Fig 4）：Charades-STA 20.6% 违反 query 唯一性，34.9% 标注精度问题；各数据集错误构成不同但总错误率都高。[F]
- TimeLens-100K（App H）：从 CosMo-Cap、InternVid-VTime、DiDeMo、QuerYD、HiREST 等多个数据集采样约 20K 视频（按时长在 0–240s 近似均匀，少量更长），用 Gemini-2.5-Pro 自动重标注：先识别分布在不同时间段的事件，再写 query 与时间戳，再自检；共约 100K 标注。训练集重标注与基准人工精修相互独立（Sec 3.4）。[F]

## 3) 起止点如何预测或选择；边界精度与容差
- 输出是文本形式的连续时间戳（秒，保留一位小数，App C.2）；帧 2 FPS，Qwen2.5-VL-7B 为基础模型，GRPO，reward = IoU(Ŝ,S*)（thinking-free，Eq.6），无格式 reward（App C.1）。[F]
- 时间戳编码（Sec 5.1，Table 2；全部在 RLVR 后比较，App F）：比较 position-embedding（MRoPE 等）、visual overlay、non-interleaved 文本前缀、interleaved 文本前缀，各自 raw 时间戳与帧序号两种格式。interleaved + raw 最优，Charades/ANet/QVH mIoU = 48.3/43.1/56.7；non-interleaved raw 为 45.8/35.2/42.8；interleaved/non-interleaved frame-index 与 overlay 数字见 Table 2（我只逐格核对了 raw 行与几个对照行，其余 [V]）。位置嵌入类方法需大规模重训、表现差。[F]
- 难度采样：先离线推理得 d_i=1-IoU，按高斯权重采样（μ=0.05，σ=0.2）；早停：当 temporal-IoU reward 与组内 reward 标准差进入平台期即停（Qwen2.5-VL 约 310 步≈2.5K 样本）。[F]
- 容差与精度度量：R1@{0.3,0.5,0.7} 与 mIoU；没有 0.9、没有秒级误差。关于精度的间接证据：Table 5 训练数据消融——用原始噪声数据训练 Charades R1@0.7 仅 14.0、mIoU 35.6，用 TimeLens-100K 为 28.1、48.3；R1@0.3 52.6→70.0。即标签质量对高 IoU 阈值影响最大（R1@0.7 翻倍）。App F 也把 Time-R1 在 Charades（"定位精度需要更高"）上的落后归因于其训练数据更噪。[F]
- "回归 vs 候选切点"：本文所有臂都是自由生成连续文本时间戳，无候选选择对照。[F]

## 4) 多解评测处理
- 评测单一真值段；"exhaustiveness"准则用来剔除多解 query（保证段外无其它满足 query 的片段），即通过数据清洗把多解问题消除，而不是在指标里容纳。[F]
- 无多参考、无集合召回、无 judge。[F]
- 重要发现：评测数据质量会重排模型（Fig 2a）：旧基准上闭源模型（如 Gemini-2.5-Pro）得分偏低、开源模型偏高；精修后闭源明显更好、开源大幅下降（Sec 3.3 Finding 2）。[F]

## 9) 与我们方向的具体差异
- 它：query 条件、单段、平均 108 秒、仅画面、只用连续文本时间戳 + IoU reward。我们：无 query（或 hook/engagement 条件）、K 个 clip、30 分钟–数小时语音视频、起止需对齐语言/镜头边界。[I]
- 可借鉴：(i) 标注准则里的 "annotation precision / exhaustiveness"，可改写成"边界是否截断句子/是否含无关尾部"；(ii) 难度采样 + 早停配方；(iii) 标注噪声会让高 IoU 阈值失效的实证（Table 5）。[I]
- 对新颖性的影响：它说明 IoU 类 reward 在 clean 数据上有效，但对"多个可接受边界/多个可接受 clip"没有任何处理；"候选切点上选择"这一设计在本文与其引用内容里均未被对比，新颖性空间仍在。[I]
