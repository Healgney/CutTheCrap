# 长视频 → 可独立成立的短 clip：文献调研报告

> 日期 2026-10-15。证据标注沿用仓库约定：`[F]` 一手来源确认 · `[I]` 推断，可被证伪 · `[V]` 待核实。
> 配套文件：`litreview_table.csv`（80 篇，24 篇 core）、`agents/*/search_log.md`（查询记录）、`seed_verification.md`、`deep/`（core 深读记录）、`ips_transferability.md`。
> 文中 `A01`、`B21` 等是 `litreview_table.csv` 的 id。
> **检索工具：** WebSearch、WebFetch、arXiv API、OpenAlex API、GitHub API、Semantic Scholar（匿名限流，只能小规模使用，前向引用不完整）。Undermind / Elicit / Asta 需要登录，未使用。
> **阅读深度：** 80 篇中 24 篇 full-text、40 篇 sections 级、16 篇仅摘要；仅摘要论文的数字未当作已验证事实。

---

## 1. 结论摘要

- **RQ1** 未找到任何工作在语音 clip 上定义自包含性并用人评验证 [F，36 条记录在案的 query]；最近邻是 Spotify 播客预览（只有二值人评）、Bridging Context Gaps、Decontextualization。
- **RQ2** 高光文献里没发现对 Most Replayed / 弹幕 / 播放量做 propensity 或因果去偏 [F，引文覆盖不全]，只有"前 5 秒置零"类补丁。
- **RQ3** "连续回归 vs 候选切点"的受控消融未找到；AntPivot 是候选切点 + DP 的最近先例，但在金融直播、片段约 200 秒。
- **RQ4** 多参考评测最近邻是 MEDit-Bench；LLM judge 只在系统级可信（ρ=0.93），单件 κ ≤ 0.18。
- **RQ5** 转写贡献最大；播客里唯一受控音频数字是 Rhapsody 的 +3.8 点命中率。
- **最大新颖性风险：** PodReels 与 Spotify 预览已占据"挑自包含片段"的概念，创新只能落在度量、验证和它与互动信号的交互上。

## 2. 领域地图

**簇 1 长转短与工业系统。** 最直接的是 Repurpose-10K（A01，AAAI 2025）：120,925 个 clip、8,398 个视频，标签来自 OpusClip 用户的 like/post 与手动修剪，但最佳平均 tIoU 只有 11.57，tIoU@0.9 仅 1.57 [F]。HIVE（A02，EMNLP 2025 Industry）面向短剧，随机边界会把 Hook 率从 0.71 拉到 0.28 [F]。Vidi 系列（B01、A04）的"高光 + 标题"只有定性演示，没有数字 [F]。播客侧有 PodReels（A10）、Spotify 预览（C03）。OpusClip / CapCut 只有厂商文档，没有可核的算法或验证 [F，A25]。

**簇 2 行为标签高光。** Mr.HiSum（A05，31,892 视频，Most Replayed）、SVHighlights（A06，320 个平均 120 分钟的体育视频，官方整场↔官方集锦配对）、Rhapsody（C04，13,364 集播客）、TVHighlights（A07）、KLive（A08）。TVHighlights 的视频其实很短（训练平均 50.6 秒，测试平均 134.9 秒），数据尚未公开 [F]；KLive 声称会发布但仓库只有占位 [V]。

**簇 3 MLLM 时间定位。** TimeLens（B02）、Time-R1（B03）、"How Should Video LLMs Output Time?"（B05）、Vidi/VUE-TR（B01）。共同点是边界都是自由生成的连续时间戳；评测多止于 IoU 0.7 [F]。

**簇 4 语音与播客 NLP。** TREC Podcasts（C01、C02）、PODTILE（C05）、YTSeg（C06，转写上的话题边界 F1 只有 43–46）、幽默与笑声（C10–C12）、pull quote（C13）。播客侧的任务定义要么是固定窗口检索，要么只做摘要，没有一个涉及边界精度 [F]。

**簇 5 篇章连贯与自包含。** Decontextualization（C14）、Bridging Context Gaps（C15）、ExtEval（C17）、SNaC、BooookScore、Referential Dangling（C20，2026 预印本）。这些给出了可借用的度量思路，但全部是文本，没有口语验证 [F]。

**簇 6 评测方法学。** Otani 2019（B17）、MEDit-Bench（B21）、Timeline-Bench（B22）、VlogReward（B23）、Stiennon 2020（B24）、MT-Bench（B25）。

**簇 7 去偏。** Joachims 2017（D01）、位置偏差估计（D02–D04）、duration 去混杂（D06）、反事实 clickbait（D07）、Baidu-ULTR 复盘（D05）。全部来自推荐 / 搜索，不是视频高光。

**簇 8 互动预测。** SnapUGC（D20）、VQualA 2025（D21）、MVP（D23）。预测的是整条 5–60 秒短视频的 P(观看 >5 秒)，不是长视频内部的片段 [F]。

## 3. 逐个 RQ 的证据

### RQ1 自包含性

**现有最强做法。** 没有一个直接度量。三条相邻路线：
- **Spotify 预览（C03）：** LLM 挑约 1 分钟、句边界对齐的"自包含片段"。但它的 "understandability" 题其实问的是"预览是否帮助判断相关性"，"contextual clarity" 允许把节目元数据当上下文；两题都是二值，约 20 名评分者、238 条标注，没有一致性数字 [F，深读核实]。
- **PodReels（A10）：** 形成性研究把"清晰的上下文"和悬空指代（"here"、"them"）列为失败模式；但选段用的 GPT-4 prompt 里没有任何相关指令，上下文完全靠人工补句 [F]。
- **文本侧：** Decontextualization（C14）给出形式化定义，但标注者一致性 κ 只有 0.30（众包）/ 0.51（专家）；ExtEval（C17）的悬空指代检测与人类标签相关 r=0.48 / 0.61，仅在新闻上验证；C15 度量了摘录离开语境后的理解度下降（3.43，补上下文后 4.13），做法是补上下文而不是挑片段 [F]。

**关键数字与可迁移性。** 口语共指显著变差：同一类系统在 AMI 会议上 63.96 F1，书面文本约 83–84 [F，C22、C23，金标转写]。SNaC 里"缺少对事件 / 对象的指代"这类标注一致性很低（专家 α=0.25，众包 0.10）[F]，所以"缺前文事件"这类标签很可能不可靠 [I]。

**仍未解决。** 没有人把自包含性分解（悬空指代 / 缺铺垫 / 问而无答 / 笑点无铺垫）并在口语 clip 上验证；没有人测过自包含性与互动信号的交互，例如高回放时刻是否因为处在剧情高潮而更不自包含 [I]。

**最近邻与区别。**
1. **C03 Spotify 预览：** 一集一个预览、无 K 个排序、无互动标签、无边界评测、无已验证的自包含度量。区别是我们要的是"可分解、可自动计算、经人评验证"的度量，以及它与互动的交互。
2. **A10 PodReels：** 同域同长度（15–45 秒），但是人机协作工具，没有基准和自动指标。
3. **C15 Bridging Context Gaps：** 修复而非选择；文本；无正式指标。

### RQ2 自然监督与去偏

**现有最强做法。** 标签来源有六类（见第 5 节表）。偏差处理几乎都停留在"承认"或"补丁"：
- Mr.HiSum 自述两条局限：部分重看的计法不明；热度图在 5 万次观看后才显示，存在自我实现偏差，且无法移除 [F]。其用户研究显示 Most Replayed 与人类多数票一致率 64.8%，不一致 19.6% [F]。
- Rhapsody 观察到 75% 的集在第 1 段有高光，把第 2 段的值复制给第 1 段 [F]；TripleSumm 把前 5 秒置零 [F]。两者都是固定窗口，没有敏感性分析，也没有人评验证修正是否更好。
- Sahu & Pandey（D17，N=48，预印本）用 [1,t,t²] 或样条基函数回归控制位置，探针相关从 0.47 降到 0.14 [F]。这是评测侧控制，不产生去偏的训练标签。

**其他领域的做法与迁移性。** IPS 的无偏性要求每个相关项的 propensity >0，且曝光只依赖位置 [F，D01]；点击模型需要会话级日志；干预采集需要多个排序器的日志。公开的 Most Replayed 只给归一化回放分数，不给留存、不给路径 [F]，所以这些方法**直接不可用**（见 `ips_transferability.md`）。可以用的是协变量调整：位置塔回归、duration 分层、频道分层、标题 / 缩略图的曝光分支 [I]。需要警惕：Baidu-ULTR 上标准 ULTR 方法在真实日志里几乎没有排序增益 [F，D05]；MVP（D23）里去掉上传者特征，MAPE 从 0.1754 升到 0.3010，去掉视频 embedding 只升到 0.1818，说明基于播放量的标签被频道主导 [F]。

**仍未解决。** 标题 / 缩略图效应、频道热度、候选工具选择偏差在高光文献里都没人处理。Repurpose-10K 的 clip 来自 OpusClip 自家候选，用户再挑选和修剪，这一选择结构的影响没人量化 [I]。

**最近邻与区别。** Rhapsody（C04）、TripleSumm（D13）、D17。区别：它们都是固定窗口的标签补丁或评测侧控制；我们要问的是，用协变量调整得到的标签，是否比补丁在**人类 clip 偏好**上更一致。

**注意：** "没找到"只代表引用图内的结果（Mr.HiSum 约 35 篇前向引用，其中 9 篇读了摘要，其余只看标题）。Semantic Scholar 关键词检索没跑完，CHI 2025 的 Most Replayed 论文（D19）全文读不到（ACM 返回 403）[V]。

### RQ3 边界即结构化预测

**现有做法。**
- **连续时间输出：** Repurpose-10K 的 IoU 回归头（平均 tIoU 11.57）；Vidi 与 TimeLens 的文本时间戳；B05 的受控三臂对比（文本数字 / 时间 token / 连续分布头）全部输出自由时间，且视频只有 30–150 秒。结论是输出接口本身对精度影响巨大：0.5B 的连续头 mIoU 43.4 超过 8B 的文本数字 27.5 [F]。
- **候选切点选择：** AntPivot（A09）以语句为候选切点 + DP 解码，有 Boundary F1（±5 秒）[F]；SVHighlights 的 TF-Selector 合并 ASR 句子横跨的镜头，避免句中切断 [F]；HIVE 用场景候选加 LLM 选开头结尾，随机边界会让 Hook 率从 0.71 掉到 0.28 [F]；PodReels 以句子为编辑单位 [F]。

**直接对比：未找到。** 要求同骨干、同数据、只在"连续回归"与"离散候选选择（可再微调）"上不同、且报告边界精度。我读过的 7 篇相关论文全文里没有这一臂；补充检索只得到工程博客和专利（不作证据）。最接近的间接证据是 QVHighlights：DETR 式回归 R1@0.5 高 6.2 点（52.89 对 46.69），mAP@0.75 低 5.3 点（29.40 对 34.67），但差异混杂了整个架构 [F]。

**边界精度的评测很弱。** TimeLens 报告止于 IoU 0.7；MEDit 里人类 leave-one-out 的 R@0.7 仅 0.033 [F]；没有任何指标检查"切在句中"或"留下悬空指代"[I]。Margin MCC（B18）专门针对带容忍窗 F1 被随机预测"充高"的问题，但只拿到摘要，ACM DL 返回 403，按约定降级为摘要级背景引用 [F]。

**最近邻与区别。** B05（唯一受控消融，但无候选臂）、A09 AntPivot（候选 + DP，但是 212 秒片段、金融域、无互动信号）、B02 TimeLens（标注质量主导排名，但是有 query 的短视频）。

### RQ4 多解评测

| 协议 | 代表 | 与人类对齐的数字 |
|---|---|---|
| 多参考 F1 + 随机基线 | Otani 2019（B17） | TVSum 上随机 0.57–0.58 ≈ SOTA 0.58–0.64，甚至不低于人类 leave-one-out 0.54 [F] |
| 与每位标注者的秩相关 | Otani τ/ρ | TVSum 人类 τ=0.177，方法 0.02–0.04 [F] |
| 集合级匹配 | MEDit cut-F1、VUE-TR 并集 IoU | 人类 leave-one-out R@0.7 仅 0.033 [F] |
| 成对人类偏好 | Timeline-Bench（43 名剪辑师） | 单判断 α=0.103；系统级可靠性 0.84 [F] |
| LLM judge | MEDit、MT-Bench | MEDit：位置摆幅 35.4pp，judge 与人类一致率 59.9%、κ=0.18；MT-Bench：GPT-4 与人 66%，人与人 63% [F] |
| 人类校准 judge 面板 | Timeline-Bench | 系统级 ρ=0.93；单件 κ=0.15 [F] |

**需更正的一处。** 我在中间汇报里把 MEDit 的 62.1%（judge 双序平均后的 AI 胜率）当成确定结果。深读发现它和主文 Table 3 的 72.8% 矛盾，judge 型号在不同章节也不一致，需要向作者确认 [V]。VlogReward（B23）的基准真值是 AI 辅助打分加合成降质，没有独立人类相关数字，不能当作"已验证"[F]。

**仍未解决。** 没有专门针对"长视频选 clip"的 judge–人类验证；没有同时满足"集合级（覆盖 / 冗余 / 排序）+ 多参考 + 人类偏好"的协议 [I]。

**最近邻与区别。** B21 MEDit-Bench 是最近的评测设计对标（多参考、cut-F1、judge 失败记录），但它纯视觉、成片 1–3 分钟、没有语音，条件是 message 而不是互动或自包含；B22 评的是整条成片而不是 K 个 clip；B17 评的是 2019 年的摘要帧重要性。**MEDit 抢占了"多参考评测"叙事，我们必须明确区分。**

### RQ5 转写之外的信号

| 论文 | 对比 | 数字 | 局限 |
|---|---|---|---|
| Rhapsody（C04） | 文本 vs 文本 + HuBERT | 命中率 0.452 → 0.490 | 单次运行、无置信区间；时间平均的 HuBERT，不是笑声专用 |
| Repurpose-10K（A01） | A+V vs A+V+字幕 | tIoU 10.31 → 10.75 | 绝对值很低 |
| SVHighlights（A06） | 仅字幕 vs 加转写 | HIT@1 15.00 → 21.25（全部 26.56） | 体育；"音频"只是音量 |
| AntPivot（A09） | 文本 vs 文本 + 说话人 | AP 67.2 → 67.8（全部 68.9） | 金融直播 |
| 幽默（C11、C12、C10） | 文本 vs 文本 + 音频 | Friends 62% → 78%；TED 64.44 → 64.47 | 有罐头笑声的情景喜剧可能泄漏；TED 几乎无增益 |
| SnapUGC（D20） | 加转写 | 无增益 | 短 UGC，约 30% 视频有可用转写 |

结论 [I]：对 talk-like 内容，转写贡献最大，通用音频特征增益很小；没有任何论文对笑声 / 掌声 / 韵律在**播客 clip 选择**上做过独立消融。VQualA 冠军"音频有用"的说法来自两个不同 backbone 的对比，不是音频开关消融 [F]。

### 对工作假设 clip value = engagement × self-containedness × boundary quality 的评估

三个因子各自都有先例，但**乘法形式没有任何证据支持，也没有任何证据反对** [I]。
- engagement 有行为标签先例（Most Replayed、OpusClip 的 like/post），但这些标签的偏差没有被处理（RQ2）。
- self-containedness 只有人评量表（Repurpose-10K 的 1–5 分 Completeness：随机 clip 1.62，专业剪辑师 3.74，数据集标注 3.42，评分者 10 人，但论文未定义该构造，也未报告一致性），没有自动度量（RQ1）。
- boundary quality 有消融的间接证据（HIVE 随机边界使 Hook 率从 0.71 降到 0.28），但没有专门度量（RQ3）。

三者之间的相关性与交互没有人测过。如果高回放时刻系统性地更不自包含，乘积形式就有意义；如果两者基本独立，乘积与加权和差别不大；如果两者正相关，则自包含性只是 engagement 的冗余信号。这是整个假设里最便宜、也最该先检验的一环，对应第 7 节的 Q2。

## 6. 评测方案建议

| 方案 | 做法 | 已知缺陷 |
|---|---|---|
| 多参考 + 容忍窗 F1 | 在多个时间容忍度（如 ±2 / ±5 秒）下报告 K 个 clip 的匹配 F1，并报告边界误差的秒级分布 | 参考一致性很低（MEDit 人类 R@0.7 仅 0.033），必须报随机基线和人类上限；Otani 已证明随机可以追平 SOTA |
| 机会校正指标 | Margin MCC 一类 | 只有摘要，无法确认计算细节 `[V]` |
| 与标注者的秩相关 | 对每位标注者的重要性序列算 τ/ρ | 人类自身也很低（τ=0.177），绝对值难解释 |
| 成对人类偏好 | 剪辑师 / 众包两两比较，双序呈现 | 单判断一致性低（α=0.103），需要多评分者，必须报人–人上限 |
| LLM judge | 双序评估，只做系统排序 | 位置摆幅 35.4pp；单件 κ ≤0.18；不能当作单个 clip 的评分 |
| 自包含性（新增） | 分解的 rubric + 多评分者 + 报告 κ | 文本先例 κ 在 0.30–0.51；口语上无先例 `[I]` |
| 边界缺陷率（新增） | 切在句中 / 说话人轮次中的比例；悬空指代率 | 没有现成度量；悬空指代检测在口语上未验证 |
| Hook 率 | 人评开头是否抓人（HIVE 风格） | 依赖具体提示词与评分者 |

**建议的默认组合 [I]。** 不要只用一个指标。第一层用多参考加容忍窗 F1，并强制报告随机基线和人类 leave-one-out 上限，用来防止 Otani 指出的"随机追平 SOTA"。第二层用成对人类偏好，每对双序呈现，评分者数量要足够估计人–人一致率；这是唯一不依赖参考答案的层。第三层才是 LLM judge，且只用于系统排序和开发期的快速迭代，不用于论文里的单件结论。自包含性和边界缺陷率作为独立的诊断指标单独报告，不并入总分，原因是它们的度量本身还没有被验证，并入总分会把未验证的构造带进主结果。

## 7. 候选研究问题

按 研究价值 × 可行性 × 新颖性风险 的综合判断排序 `[I]`。

**Q1 自包含性是否是一个可分解、可由人类一致标注、且可自动近似的构造？**（价值高、可行性高、新颖性风险中）
- 可证伪陈述：在 ≥200 个播客 clip 上，分解 rubric 的评分者间 κ 达到 0.4 以上，且某种自动打分与人评的相关高于"只用时长"的基线。
- 第一个决定性实验：标注一个 200–300 个 clip 的试点（分悬空指代 / 缺铺垫 / 问而无答 / 笑点无铺垫四项），比较 ExtEval 风格的共指与话语标记规则、一个 LLM judge、以及长度基线。若 κ <0.3，或自动打分不优于长度基线，则判伪。
- 风险：C03 和 PodReels 已占据概念；价值在于度量与验证。

**Q2 互动信号与自包含性是否存在交互？**（价值最高、新颖性风险低、依赖 Q1）
- 假设：高回放时刻因为处在叙事高潮而更不自包含，所以"只挑最热"会选出看不懂的 clip。没有任何论文测过 [I]。
- 第一个决定性实验：用 Rhapsody（需申请 gated 数据）的回放热度，与 Q1 的打分做相关；再用成对人评比较"最热 top-K"、"最自包含 top-K"、"二者乘积 top-K"。若乘积在人类偏好上不优于单项，则判伪。

**Q3 在语义候选切点上选择，是否优于连续时间回归？**（价值中、可行性高、新颖性风险低到中）
- 第一个决定性实验：同骨干、同数据的四臂对比（文本时间戳 / 时间 token / 候选选择 / 候选 + 微调），评测用容忍窗 F1、"切在句中"比例和一次小规模人评。动机证据：HIVE 里随机边界使 Hook 率 0.71 → 0.28。
- 风险：审稿人可能认为太工程；Repurpose-10K 的划分泄漏需要先清理。

**Q4 对回放热度做协变量调整，是否比"置零前 5 秒"更贴近人类 clip 偏好？**（价值中、可行性中、新颖性风险低）
- 第一个决定性实验：在 Mr.HiSum / Rhapsody 上比较原始标签、固定窗口补丁、位置塔回归三种标签，用一个小型人类成对偏好集评估一致率。若调整没有超过补丁，则判伪。
- 限制：公开数据拿不到留存与曝光，无法得到 IPS 的无偏保证，只能称为 bias reduction。

**Q5 LLM judge 在 clip 级评测上是否能达到人–人一致率的上限？**（价值中、可行性中、新颖性风险中）
- 第一个决定性实验：100 对 clip，人类成对比较与 judge（双序）比较，报告单件 κ，并与人–人 κ 对比。若 judge 低于人–人上限，则只能用于系统级排序，与 Timeline-Bench 和 MEDit 的结论一致。

**依赖关系。** Q1 是 Q2 和 Q5 的前提：没有经过验证的自包含度量，交互效应无从检验，人评协议也缺一个可以被 judge 复现的维度。Q3 和 Q4 相对独立，可以并行推进，也可以在 Q1 之前先做。如果只能做一个，我会选 Q1，因为它同时是一个独立的贡献（度量与标注协议）和其余问题的基础设施。无论选哪个，第一步都不依赖新的大规模数据：Q1 需要约 300 个 clip 的标注，Q3 可以在清理后的 Repurpose-10K 上做，Q4 和 Q5 需要的是小型人类偏好集。

## 8. 风险与未知

**版权与数据发布。** Repurpose-10K 只提供标注，视频需自行下载，YouTube ToS 限制再分发；Rhapsody 的数据 gated 且许可未写；SVHighlights 是 CC BY-NC 4.0；TVHighlights 未公开；MEDit-Bench 与 SnapUGC 的数据许可未写 `[V]`。若要发布新数据，仓库既有做法"只发 URL + 时间戳 + 标注"仍然适用，但平台 ToS 需要逐一核对。

**大厂已有工作。** Vidi（字节，代码许可 NOASSERTION）与 Spotify 预览（ACL 2025 Industry）都有产品化信号；OpusClip 的 Virality Score 只有厂商说明，没有公开验证 [F]。

**证据薄弱处。**
- 16 篇仅摘要；Margin MCC、GF-measure、VISIOCITY 的计算和人类相关数字未读。
- Repurpose-10K 的统计矛盾（clip 中位数、划分泄漏）是 Agent A 用发布的 JSON 自己算的，我没有独立复现，引用前应复核 `[I]`。
- HIVE 摘要写 800+ 集、正文写 2,582 集；PodReels 摘要与讨论节对时间 / 心理负荷降幅的表述不一致；MEDit 的 62.1% 与 72.8% 矛盾 [F，各自论文内部]。
- VlogReward 没有独立的人类相关数字；Referential Dangling（C20）是预印本。
- "没找到"类结论（RQ1、RQ2、回归 vs 候选切点）只代表我能触达的来源：Semantic Scholar 全程限流，OpenAlex 的引文覆盖较差，所以前向引用不完整。

**与仓库主线的关系未决。** 仓库 README 与 `docs/00-status-overview.md` 的现行主线是"从专业短片反推 crop trajectory"。本调研的方向（长语音视频 → 时间选择，裁切明确不在范围内）是另一条固定方向。我没有改动任何既有文档，两者如何取舍由你决定。

## 9. 优先阅读清单

1. **PodReels**（[2311.05867](https://arxiv.org/abs/2311.05867)）：最近的概念与领域邻居，先读它才知道"挑自包含片段"已经做到什么程度。
2. **Spotify 播客预览**（[2505.23908](https://arxiv.org/abs/2505.23908)）：唯一的生产级先例，看清它的评测缺口。
3. **Repurpose-10K**（[2412.08879](https://arxiv.org/abs/2412.08879)）：最近的数据与任务定义，同时要知道它的清洗问题。
4. **AntPivot**（[2206.04888](https://arxiv.org/abs/2206.04888)）：边界作为结构化预测的最近先例。
5. **MEDit-Bench**（[2607.25300](https://arxiv.org/abs/2607.25300)）：评测设计对标，也记录了 judge 失败。
6. **Timeline-Bench**（[2609.35143](https://arxiv.org/abs/2609.35143)）：校准 judge 的完整配方与可靠性边界。
7. **Rhapsody**（[2505.19429](https://arxiv.org/abs/2505.19429)）：唯一的播客高光数据集，带音频消融和"第一段"补丁。
8. **Otani 2019**（[1903.11328](https://arxiv.org/abs/1903.11328)）：多解评测问题的源头。
9. **Decontextualization**（[2102.05169](https://arxiv.org/abs/2102.05169)）：自包含性唯一的形式化定义，也是标注一致性的警示。
10. **Joachims 2017**（[1608.04468](https://arxiv.org/abs/1608.04468)）：去偏的理论模板，读它是为了看清 IPS 在我们场景里缺哪些观测量。
