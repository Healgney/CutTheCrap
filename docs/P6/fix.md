## 2. 条件边界指标（只在 IoU 匹配对上统计）

**定义：** 先按 IoU 做一对一贪心匹配（阈值 0.5，另报 0.3）；只在这些匹配上的 pred–GT 对里，统计起点/终点绝对误差的**中位数**，以及误差 ≤0.5/1/2 s 的**比例**（分母 = 匹配对数）；同时报告匹配对数。random 的数值是 10 次运行的逐次中位数/比例的均值±标准差。

**观察（重要）：**

1. **即使 IoU≥0.5 匹配上，臂 A 的边界误差中位数约 10 s**。GT 片段中位时长 34.9 s，10 s 的边界误差仍能与 GT 达到 IoU 0.5–0.8（已抽查 5 例确认，如 pred(2113.9,2153.8) vs GT(2105.2,2156.3)，IoU 0.78、起点误差 8.8 s）。这说明臂 A 的问题**首先是定位粗**（1 s 网格回归 + 特征切片），而不是"选错片段"。
2. **臂 C 的吸附把 ≤0.5 s 的精确命中率从 3.2% 提到 7.4%（起点）、2.9% 提到 7.1%（终点）**，约 2.3 倍；误差中位数基本不动（10.0→10.2），因为 28.1% 的预测边界离任何句边界 >3 s，吸附无从下手。这与臂 C 报告中"bF1 只涨 0.006"的解释一致，并给出了更直接的证据。
3. **random 的边界误差中位数反而更小（6.8/7.1 s）**：它的片段时长来自 GT 分布，起止点均匀撒在块内，更"居中"；但它在 ≤0.5 s 上的命中率低于臂 C，且 F1@0.5 更低。这再次说明单一指标都不足以定论，需要 F1 + 条件边界 + midsent 三者一起看。
4. 条件指标对臂 D 是更清晰的靶子：如果 D 的候选解码有效，IoU≥0.5 匹配对数应显著高于 672，且起点误差中位数应降到 1–2 s 量级。

## 3. 原始划分的 random 基线（与 11.57 对比）

**实现：** `l2s/eval/random_original_split.py`。只用 `third_party/repurpose/data/test.json`（**1,122 块、12,025 个 GT 片段**，不需要特征），原协议：每块 k = ceil(分钟×0.3)、块内均匀撒点、`calculate_tiou` 逐字复制、逐块算 5 个阈值均值再对块平均。10 次运行（seed 1234+r）。自检：GT 当预测 = 1.000000。

预测片段数：7,137/次（0.3 段/分钟预算，块长上限 1800 s → 每块 1–9 个）。原始 JSON：`reports/P6/random_original_split.json`。

**观察：**

1. **论文的 11.57 只比随机高 2.2–3.8 个点**（相对提升 1.23×/1.50×）。在"只算精度 + 0.3 段/分钟"的原始协议下，随机撒点就能拿到 7.8–9.4，这与 docs/07 §1 里"原指标是 precision、预测数远少于 GT 数"的判断一致，而且是**量化证据**，建议直接写进论文的评测修正一节。
2. (b) 固定 36 s 比 (a) 高 1.6 个点：原始协议下，用真人的时长分布反而不占优，说明该指标对"片段时长是否像真人"不敏感，进一步说明它不能作为定位能力的证据。
3. 需要提醒：这一项与臂 A/C 不可直接对比（不同划分、不同分母；原始划分没有特征，臂 A 无法在其上推理）。它只用于标定论文主指标的随机水位。
