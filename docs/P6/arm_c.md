# 臂 C：回归 + 吸附到句子边界

**结论：** 吸附把句中切断率从 0.65 降到 0.26/0.24（−0.39/−0.41，且低于 GT 自身的 0.36/0.46），但对 GT 边界的对齐（bF1@1s）几乎不动（+0.006，远低于 +0.10 的显著线）——按 §1.4 属"臂 C 和臂 A 几乎一样"档，**报告后停下等审核**。臂 D（候选选择）在边界对齐上有巨大空间（P4 天花板 bF1@1s ≈ 0.74 vs 臂 C 0.019）。

## 输入

- 臂 A 预测来源：**本机不存在、Repurpose 官方也无**（无发布 checkpoint）→ 按批准的简化复现（G1 减配版）自行训练生成：`third_party/repurpose/arm_a/`，种子 1234，best.pth（sel avg tIoU 0.1035 @ epoch 32）。
- 训练集（cutoff 2026-10-26，`l2s/datasets/data_manifest.json`）：2,359 个有特征视频 = **1,672 训练**（原 train 1,186 + clean val 486，**排除 clean test 防泄漏**）+ 86 选择集（clean val 的 15%，seed 1234）+ 601 test_clean。
- 评测划分：clean test（主实验）。**原始 test 无法评测**（原划分 train/test 的特征未准备），orig_tiou 不与 11.57 直接对比（见"偏离"）。
- 句子候选：WhisperX segments，601 个可评视频平均 **351.6 句/视频**（句首 351.6、句尾 351.6）。
- 预算：orig = ceil(分钟×0.3)（原协议）；oracle = GT 段数。两种都报。

## 算法

吸附窗口 ±3 秒；起点找句首、终点找句尾；不改分数、不增删 clip；窗口内无候选点则保持原值。

- 吸附率 **71.9%**：起点 70.3%（2,242/3,189）、终点 73.4%（2,341/3,189）；未吸附 28.1% 保持原值（臂 A 边界离最近句边界 >3s）。

## 结果（clean test，601 个有特征视频；76 个无特征/ASR 的视频无预测、计 0）

### oracle 预算（预测数 = GT 段数）

数字与 orig 预算几乎相同（臂 A 输出本就受 0.3/min 上限约束，多数视频未触顶）：bF1@1s 起点 0.0119→0.0187，终点 0.0117→0.0174；midsent 0.6496→0.2588 / 0.6446→0.2270。完整数字见 `arm_a_metrics.json` / `arm_c_metrics.json`。

## 观察

1. **吸附在"句中切断率"上效果巨大**：起点 0.656→0.269、终点 0.649→0.240。注意降到了 GT 自身句中率（起点 0.360/终点 0.460，P4 G0）**以下**——吸附把边界过度推向句边界，而真人标注约 1/3 起点本来就在句中。这一"过度对齐"本身是论文可用的观察。
2. **但对 GT 边界的对齐几乎不动**：bF1@1s +0.006、bF1@0.5s +0.008（约翻倍但绝对值仍 <0.02）。三个原因：(a) GT 边界本身常不在句边界（P4：起点 36%/终点 46% 落在句中），吸附天然到不了；(b) 28.1% 的预测边界离任何句边界 >3s，吸附不动；(c) 主因是臂 A 定位粗——回归边界离 GT 太远时，±3s 吸附救不回来。
3. **对臂 D 的标定**：句边界候选的理论天花板（P4：GT 吸附到最近 sent 候选后 bF1@1s ≈ 0.74）vs 臂 C 实测 0.019——臂 D 空间巨大。臂 D 的"及格线"应至少显著超过臂 C 的 bF1@1s 0.019 和 midsent 0.26/0.24。
4. 无反常数值（无 NaN/全 0；bF1 与 orig_tiou 方向一致）。种子 1 补训已按计划在服务器后台启动（跑通后补种，2026-10-26 批准）。

## 偏离与缺口（都需审核人知悉）

1. **臂 A 是减配复现，不是 G1 原协议**：训练集 1,672 视频 vs 原 7,065（原 train 特征未准备），checkpoint 用 clean val 的 15% 选择而非在 test 上选。因此 orig_tiou 0.083 **不能与论文 11.57 对比**，只用于臂内 A/C 对比。若需对齐 11.57，要先给原 train 划分抽特征（数天工作量）。
2. **训练适配**（L4 22GB 实测约束，均已在代码注释注明）：bf16 autocast、长度分桶批（B·T≤7,200 且 B·T²≤4·1800²）、损失按实际 batch 大小归一、softnms 副本 `.float().cpu().numpy()`。
3. **76/677（11.2%）clean test 视频无特征也无 ASR**（S3 404，D1 已知的不可得视频），无预测计 0，拉低所有均值约 11%。
