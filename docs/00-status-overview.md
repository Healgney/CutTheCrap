## 01 课题 idea

### 任务定义（赛题）`[F]`

输入原始长视频、测试样本索引与 `targetRatioWH`（常见 16:9 或 9:16）；每个视频输出 JSONL，
`predictions` 中每项为 `{"frame": 帧号, "bboxes": [x, y, w]}`，每帧只允许一个框，
高度由目标画幅自动换算，无高光可交空列表。测试内容不限体育，覆盖户外、演出、旅行 Vlog、课堂、
会议与媒体素材，含抖动、遮挡、主体尺度变化与横竖屏混合。**赛方不提供训练集。**

### 指标的闭式形式与它的后果

四份文档里唯一称得上「新信息」的推导，也是论文最大的陷阱来源。它依赖附件对指标的转述——
**必须先读官方评测脚本验证**；若脚本实现与转述不符，下面若干推断需重算 `[V]`。

设 `G` 为真值高光帧集合，`P` 为预测帧集合，`S` 为交集上 IoU 之和：

```
S  = Σ iou_f          f ∈ P ∩ G

Precision = S / |P|
Recall    = S / |G|

F1 = 2S / ( |P| + |G| )
```

即一个 soft-Dice。**分母不含交集项，这是全部后果的来源。**

- 多预测一个不在 `G` 中的帧，**永远有害**：分子不变、分母加一。
- 多预测一个在 `G` 中的帧，**当且仅当其 IoU 大于当前 F1 的一半时有益**。
  推导：`2(S+u)/(D+1) > 2S/D ⟺ D·u > S ⟺ u > S/D = F1/2`。
- 所以最优决策规则是对期望 IoU 取阈值：`E[u] = P(f∈G) × E[iou | f∈G] > f*/2`。
  这是分式规划，可用 Dinkelbach 迭代求解，阈值与最终得分互为不动点。

**对课题的后果：**赛题指标本身就要求联合决策——真高光帧若构不出好框就该主动丢弃。
也就是说，你想论证的「联合性」在比赛里是*指标诱导*的，不是任务本性诱导的 `[I]`。
这既是最大的复用机会，也是评审最可能攻击的点。

**必须读官方评测脚本确认，不要靠推断** `[V]`：`|G|=0 且 |P|=0` 时的除零处理；
重复帧是否计入 `|P|`；越界框是判 0 分还是整卷无效。

### Hostile reviewer 判决：Reject（当前形态）

评审口径：输出签名（时间子集 + 每选中帧一个框）与 STVG 完全同构；没有证明 joint 建模捕捉到了
cascade 捕捉不到的交互；报告的增益与「更强 backbone + 调好的操作点」相容。最致命的一句是——
jointness 这个中心主张看起来是所选 F1 指标诱导的，而不是世界的性质。

| 最近邻威胁 | 代表方向 | 评审会怎么说 |
|---|---|---|
| ① STVG / RVOS | TubeDETR、STCAT、HC-STVG；Referformer、MTTR | 输出签名同构。头号威胁——「换了个隐式 query 的 STVG」 |
| ② 裁剪 + 检索级联 | AutoFlip 类显著性裁剪、GAIC / VFN 构图美学；配 Moment-DETR、QD-DETR、UniVTG | 「两个已解决子问题的拼接」 |
| ③ 剪辑挖掘 / VLM 直出 | Learning to Cut by Watching Movies 一类的监督挖掘；直接 prompt 强视频 LLM 输出帧号与框 | 前者威胁你的数据贡献，后者是必问的零样本基线 |

### 决定性对照实验

**Control C 与 D 应排在任何架构工作之前**——它们决定「论文主导」这条路线是否有资格存在。

| 对照 | 设计 | 若结果为此，thesis 死亡 |
|---|---|---|
| A · 同料级联 | 与 joint 模型同 backbone、同数据、同算力、同操作点的两阶段级联 | joint ≈ cascade |
| B · Oracle 分解 | 分别给 joint 与 cascade oracle 时间选择再比构图；再给 oracle 构图比选择 | joint 优势在 oracle 选择下消失 ⟹ 增益来自选择器而非联合性 |
| **C · Croppability-blind**<br>最该先做，成本最低 | 从选择头切断构图可行性信号 | 分数无可测差异 ⟹ 交互效应不存在，立刻转向 |
| **D · 反事实子集**<br>最有说服力 | 构造或筛选「内容最强但不可构图」的片段：主体被切边、双主体分离、越过画幅 | joint 模型不改选 ⟹ 你声称的机制没在起作用 |
| E · 指标外部效度 | 在人类偏好下重跑 A / C / D | 交互只在 soft-Dice 下出现、人类偏好下消失 ⟹ 你研究的是指标不是任务 |
| F · 零样本 VLM | 强视频 LLM 直接输出 frame 与 `[x, y, w]` | 打平 ⟹ 无方法贡献 |

## 02 数据收集与处理流水线

目标：在**零人工逐帧标注**的前提下，从自然存在的「长片 + 竖屏精剪短片」中，自动恢复
「哪些帧进了成片」+「每帧的裁切窗」，产出弱监督标签。完整 spec 见 [`02-data-pipeline.md`](02-data-pipeline.md)。

### 输出契约（先定死，倒推整条流水线）

`bbox` 只存 `[x, y, w]`，高度锁死于 `target_ratio`——与比赛 3-DoF 定义一致 `[F]`。

```json
{
  "src_video_id": "abc123",
  "short_video_id": "abc123_short01",
  "target_ratio_wh": [9, 16],
  "src_fps": 30.0, "src_wh": [1920, 1080],
  "pairs": [
    { "src_frame": 412,
      "bbox": [640, 0, 607],
      "conf": 0.93,
      "src_shot_id": 7 }
  ],
  "negatives_policy": "unlabeled",
  "provenance": { "source_tier": 1, "license": "url-only",
                  "extractor_version": "0.3.1" }
}
```

### 来源分层

区分原则：**时间监督（哪些帧）到处都是，空间监督（怎么裁）才稀缺。**
三条并行，任何一条断供都不致命。

> **命名变更：**源文档用 T1 / T2 / T3 命名来源梯队，与三条 thesis 的 T1/T2/T3 撞名。
> 本仓库改称 **S1 / S2 / S3**。`02-data-pipeline.md` 内文尚未同步改。

| 梯队 | 来源 | 时间 | 空间 | 域宽度 | 许可风险 | 角色 |
|---|---|---|---|---|---|---|
| **S1** 天然双画幅 | 同创作者横屏原片 + 竖屏切片；机构官网 16:9 + TikTok / Reels 9:16；直播 VOD + 官方切片 | 有 | 需反推 | 宽 | 高（平台 ToS）`[V]` | 主产能，但版权是命门 |
| **S2** 宽视野虚拟机位 | Veo / Pixellot / Spiideo 自动跟随；转播 vs 战术全景；360° 常规视场版；PTZ 讲座录制 | 有 | **直接记录** | 窄（体育 / 教室） | 中 `[V]` | 干净校准集，标定 S1 抽取器误差上界；S1 受阻时的退路 |
| **S3** 仅时间监督 | SoccerNet、MovieNet、Condensed Movies、TVSum / SumMe / YouTube Highlights | 有 | 无 | 中 | 低（学术许可清晰）`[V]` | 单独喂时间分支，用于预训练与「时间能力有多少来自灰色数据」的消融 |

### 七个阶段

| # | 阶段 | 要点 | 产出 |
|---|---|---|---|
| **0** | 合成对 + 抽取器自检<br>*今天就能做 · 永久回归集* | 用 `ffmpeg -vf "crop=608:1080:'320+200*sin(t/3)':0,scale=1080:1920"` 生成带完美真值的长/短对，真值轨迹 = crop 表达式。逐项注入退化：字幕/贴纸、变速、调色、低码率、b-roll | 中位/尾部轨迹误差——审稿人问「标签多脏」时唯一有说服力的回答 |
| **1** | 真实对小批（50–100 对，逐对人工核）<br>*决定 S1 生死* | 用人工核过的对校准阶段 5 每个阈值的 precision | **yield rate** + 失败原因分布 |
| **2** | 时间对齐（音频优先） | 核心洞察：空间怎么裁，声轨都不变。PySceneDetect 切镜头 → Chromaprint `fpcalc` 粗对齐 + chroma 互相关精修到帧级。拟合 `short_t → src_t` 斜率 ≠ 1 判变速，整对丢弃。音频失效时退到 CLIP/DINO + FAISS 帧检索 | `short_frame → src_frame` 映射 + 对齐置信度 |
| **3** | 空间配准（3-DoF 约束） | 轴对齐、定宽高比，只有 `(x, y, scale)` 三个自由度。搜索序：满高假设(1-DoF, 只搜 x) → 3-DoF 粗到细 → 丢弃。从 `cv2.matchTemplate` NCC 起步，峰值即置信度。上特征匹配时用「旋转角 ≈ 0」当有效性检验 | 逐帧 `[x, y, w]` + 配准置信度 |
| **4** | 轨迹平滑 + 验证 | 真实轨迹是平滑的，每帧跳 200px 是估计失败。Kalman / Savitzky-Golay / 轨迹级 RANSAC。平滑度过滤比逐帧阈值可靠得多——它用上了「轨迹连续」这个强先验 | 清洗后轨迹 + 每帧 `conf` |
| **5** | 丢弃规则<br>*过滤器质量 = 标签质量* | 每条丢弃理由都要计数留档。阈值见 `data_pipeline/configs/thresholds.yaml` | 丢弃分布统计 |
| **6** | 标签导出 + 质量报告 | 按契约落 JSON；同时导出可视化（源帧画框 + 短片对应帧并排）供阶段 1 抽检。`extractor_version` 写进 provenance | 标签 + 质量报告 |

### 丢弃规则

| 丢弃条件 | 检测方式 | 语义 | 起始阈值 |
|---|---|---|---|
| 音频时间轴斜率 ≠ 1 | 阶段 2 拟合斜率 | 变速 / 速度斜坡 | `slope_tolerance: 0.02` |
| 估计 scale > 1 | 阶段 3 输出 | 短片比源更宽，配错了 | `max_scale: 1.0` |
| 估计宽高比 ≠ target | 阶段 3 输出 | 加了黑边 / 匹配失败 | `ratio_tolerance: 0.03` |
| 大面积文字 / 贴纸 | PaddleOCR / EAST | 裁切可能在避让文字 = 另一个目标函数，会污染标签 | `text_area_frac_max: 0.15` |
| 含源里没有的画面 | 阶段 2 置信度骤降 | 插入了 b-roll | `xcorr_min_peak: 0.4` |
| NCC 峰值 / 内点率过低 | 阶段 3 输出 | 配准不可信 | `ncc_min_peak: 0.55` |
| 轨迹抖动超阈值 | 阶段 4 残差 | 逐帧估计失败 | `max_jump_px_per_frame: 60` |
| 分屏 / 画中画 | 版式检测 | 非单窗裁切 | — |

### 建模陷阱：未入选帧 ≠ 负样本

短片有时长上限，大量「其实不错但没被选中」的帧会被误标为负例，直接当二分类训会
**系统性压低召回**。这是 PU（positive-unlabeled）问题，必须在数据层处理，也可以写成一个贡献点。

1. 未入选帧一律标 `unlabeled`，不标 `negative`。
2. PU 损失 / 先验校正；或只在**同一镜头内部**构造对比（入选帧 vs 同镜头未入选帧），避开跨镜头假负例。
3. **偏好对天然产出**：入选镜头 vs 未入选镜头 = 一对，直接喂 DPO。对上赛方的 RL / 偏好提示，
   也对上论文立论，零新增标注。

### 全程要盯的数

| 指标 | 在哪测 | 为什么关键 |
|---|---|---|
| 合成对轨迹恢复中位/尾部误差 | 阶段 0 | 标签置信度上界 |
| **yield rate** | 阶段 1 | **决定 S1 生死的那个数，现在完全未知** `[V]` |
| 各丢弃理由占比 | 阶段 5 | 指导抽取器该修哪里 |
| 人工抽检 precision（每阈值） | 阶段 1 | 校准丢弃规则阈值 |
| 标签质量 vs 下游性能曲线 | 训练后 | 论文主结果 |
| 9:16 占比 · 高光帧稀疏度 | 样例数据 | 决定时间选择与构图哪个是一阶项 |

### 合规与发布 `[V]`

不给法律结论，仅通行做法。平台批量下载通常违反 ToS，大概率不能再分发视频本体。
领域标准做法是**只发布 URL + 时间戳 + 你导出的标注**，不发视频（HowTo100M、ActivityNet 皆如此），
这条路可发表。比赛侧无论如何要披露来源、清洗方式、许可与用途 `[F]`，披露表早建。

另需向组委会确认：用闭源 API 标注*自有训练数据*是否合规——赛规仅禁其用于**测试集推理** `[F]`，
训练数据是另一回事，但需书面确认。

## 03 架构设计

> ⚠ 本节由 [`03-repo-selection.md`](03-repo-selection.md) 整理而来，该文档**仍按「联合学习」主线写**，
> 尚未与新主线（数据 + 评测协议）对齐。三分支架构目前也**没有和数据契约对等的独立 spec**。

没有任何一个 repo 能同时匹配这个任务——query-free、画幅条件、联合高光 + 逐帧 3-DoF 构图，
这个组合目前没有开源实现。所以做法是**一个主干 + 各模块借件**，这套组装本身可以写进 method。

```
                    ┌─────────────────────────────────────────┐
                    │ 共享底座                                 │
                    │ 解码/抽帧/长视频采样 · 镜头边界检测      │
                    │ 主体检测分割跟踪 · 显著性特征            │
                    │ 画幅几何换算与合法性裁剪 · 轨迹平滑      │
                    │ 来源许可登记表                           │
                    └────────────────┬────────────────────────┘
            ┌────────────────────────┼────────────────────────┐
            ▼                        ▼                        ▼
   ┌─────────────────┐     ┌──────────────────┐     ┌──────────────────┐
   │ 主干            │     │ 几何分支         │     │ 语义分支         │
```

### 主干 · 决策头 + 评测台 —— fork [line/lighthouse](https://github.com/line/lighthouse)

统一可复现的 moment retrieval + highlight detection 库，内置 QD-DETR、CG-DETR、UniVTG、
Moment-DETR 等 7 个模型，含特征抽取与训练/评测 harness，且仍在活跃维护——这个方向上很少见。

- 选它的理由：**harness 是最贵、两个目标都要用的部分**
- 改造：文本 query 输入位置换成 `targetRatioWH` 条件
- 时间头保留；**空间头它没有，自己加**
- 不 fork 整库时的单模型基线：QD-DETR、UniVTG（后者本就统一了 interval / curve / point 三种时间标注）

### 几何分支 · 空间构图

没有现成实现，用这几个拼。输出 **x 方向的分布 + 少量尺度，不是点估计**，对应流水线阶段 3 的 3-DoF 约束。

| 用途 | Repo | 说明 |
|---|---|---|
| 主体框 + 跟踪（一体） | IDEA-Research/Grounded-SAM-2 | Grounding DINO + SAM2，文本或框 prompt 直接出可跟踪主体，最省事的入口 |
| 分割/跟踪底座 | facebookresearch/sam2 | 需要更底层控制时用 |
| 点级跟踪（平滑轨迹） | facebookresearch/co-tracker | CoTracker3。**许可地雷**——历来 CC-BY-NC 非商用 `[V]` |
| 定宽高比构图打分 | HuiZeng/Grid-Anchor-based-Image-Cropping-Pytorch | GAIC，对指定宽高比输出候选裁切并打分，正对上 3-DoF 稠密枚举。学术许可需核实 `[V]` |

### 语义分支 · VLM + 偏好优化

训练框架成熟、配方现成。DPO 的训练输入直接来自流水线的天然偏好对（入选镜头 vs 未入选镜头），零新增标注。

- 底座：Qwen2.5-VL 2B / 7B（Apache-2.0，对论文和比赛都友好；大尺寸需核实 `[V]`）

- zjysteven/lmms-finetune：最小代码库，想读懂 / 魔改微调逻辑时最清楚

## 04 未决事实与反转规则

在这些填上之前，任何「比赛优先 / 论文优先」的判断都主要在表达偏好，而不是由证据支持的决策。

| 未决事实 | 若反转，建议怎么改 |
|---|---|
| 「未公开发表」条款对 ICLR / OpenReview / arXiv 的解释 `[V]` | 从严 ⟹ 立即切策略 A：先比赛、论文延后一轮；arXiv 与开源冻结至最早允许日期，而论文的数据线继续低强度推进（它不触发公开）。不要因此放弃论文，只是改变时序 |

| GT 是稠密还是抽样标注 `[V]` | 决定几何分支逐帧还是逐段，也决定流水线导出是否要下采样对齐比赛标注粒度。**从样例数据里数一下就知道，应早于任何架构编码去确认** |
