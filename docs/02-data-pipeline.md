# 数据构建 Pipeline：长/短视频对 → 高光选择 + Crop 轨迹标签

> 目标：在**零人工逐帧标注**的前提下，从自然存在的「长片 + 竖屏/精剪短片」中，自动恢复出
> 「哪些帧进了成片」+「每帧的裁切窗 `[x, y, w]`」，产出可用于训练的弱监督标签。
>
> 标注符号沿用决策简报：`[F]` 已由赛题附件确认 · `[I]` 推断 · `[V]` 待核实。
> 本文中所有阈值均为**起始值，须在阶段 1 用真实数据校准**，不是实测结论。

---

## 0. 输出契约（先定死，倒推整条流水线）

每条样本最终落成一个 JSON，字段与比赛输出格式对齐 `[F]`，并额外携带训练所需的元信息：

```json
{
  "src_video_id": "abc123",
  "short_video_id": "abc123_short01",
  "target_ratio_wh": [9, 16],
  "src_fps": 30.0,
  "src_wh": [1920, 1080],
  "pairs": [
    {
      "src_frame": 412,
      "bbox": [640, 0, 607],          // [x, y, w]; h 由 target_ratio 换算，与比赛一致
      "conf": 0.93,                    // 该帧标签置信度（供 PU / 加权训练用）
      "src_shot_id": 7
    }
  ],
  "negatives_policy": "unlabeled",     // 见 §9：未入选帧一律 unlabeled，不当负例
  "provenance": { "source_tier": 1, "license": "url-only", "extractor_version": "0.3.1" }
}
```

**关键约束**：`bbox` 只存 `[x, y, w]`，高度锁死于 `target_ratio`——与比赛 3-DoF 定义一致 `[F]`，避免下游还要处理 h 的自由度。

## 1. 数据来源分层

区分原则：**时间监督（哪些帧）到处都是，空间监督（怎么裁）才稀缺。** 按「能否拿到裁切轨迹」分三梯队。

| 梯队 | 来源 | 时间监督 | 空间监督 | 域宽度 | 许可风险 |
|---|---|---|---|---|---|
| **T1** 天然双画幅 | 同创作者横屏原片 + 竖屏切片；机构官网 16:9 + TikTok/Reels 9:16；直播 VOD + 官方切片 | ✅ | ✅ 需反推 | 宽 | 高（平台 ToS）`[V]` |
| **T2** 宽视野 + 虚拟机位 | Veo/Pixellot/Spiideo 自动跟随；转播 vs 战术全景；360° 常规视场版；PTZ 讲座录制 | ✅ | ✅ **直接记录，几乎无配准噪声** | 窄（体育/教室） | 中 `[V]` |
| **T3** 仅时间监督 | SoccerNet（全场+集锦）、MovieNet（正片+预告）、Condensed Movies、TVSum/SumMe/YouTube Highlights | ✅ | ❌ | 中 | 低（学术许可清晰）`[V]` |

**策略**：
- **T1 是主产能**，但版权是命门 → 决定发布方式（见 §11）。
- **T2 是干净校准集**——配准噪声极低，用来标定 T1 抽取器的误差上界，也是 T1 发布受阻时的退路。
- **T3 单独喂时间分支**，用于预训练与「时间能力有多少来自灰色数据」的消融回答。
- **不要单押 T1。** 三梯队并行，任何一条断供都不致命。

## 2. 阶段总览

```
[阶段0] 合成对 + 抽取器自检      ← 今天就能做，不需要任何真实对
   │  产出：已知真值的合成 pair，量出恢复误差与失败模式
   ▼
[阶段1] 真实对小批 (50–100)      ← 逐对人工过一遍，量 yield rate
   │  产出：yield rate + 失败原因分布 → 决定 T1 是否划算
   ▼
[阶段2] 时间对齐 (音频优先)      ← 短片镜头 → 源时间轴
   ▼
[阶段3] 空间配准 (3-DoF 约束)    ← 每帧裁切窗
   ▼
[阶段4] 轨迹平滑 + 验证          ← 野点过滤
   ▼
[阶段5] 过滤/丢弃规则            ← 决定标签质量
   ▼
[阶段6] 标签导出 + 质量报告      ← §0 的契约
```

**阶段 0 必须先跑完再碰真实数据**——它决定后面所有标签的置信度上界。

---

## 3. 阶段 0：合成对（bootstrap + 永久评测集）

拿任意横屏视频，用自指定轨迹生成竖屏版 → 得到**带完美真值**的长/短对。

```bash
# 生成一个 x 随时间正弦摆动的 9:16 竖屏切片（源 1920x1080）
ffmpeg -i src.mp4 \
  -vf "crop=608:1080:'320+200*sin(t/3)':0,scale=1080:1920" \
  -c:a copy synth_short.mp4
# 真值轨迹 = crop 表达式，逐帧可解析
```

**用途**：
1. **抽取器精度评测**：recovered `[x,y,w]` vs 已知真值，报中位/尾部误差。
2. **失败模式可控注入**（每种单独测，画退化-误差曲线）：
   - 字幕/贴纸叠加（`drawtext` / overlay PNG）
   - 变速与速度斜坡（`setpts`）
   - 调色（`eq` / `curves`）
   - 低码率重编码（`-crf 32`）
   - 插入 b-roll（concat 非源片段）
3. **一个能写进论文的数字**：抽取器在合成对上的中位轨迹误差——审稿人问「标签多脏」时唯一有说服力的回答。

> 阶段 0 的产出是**评测集**，不是训练集——它要一直留着，每次改抽取器都回归测一遍。

---

## 4. 阶段 2：时间对齐（音频优先）

**核心洞察：空间怎么裁，声轨都不变。** 把困难的视觉检索降级为信号处理。

```bash
# 1) 声学指纹粗对齐
fpcalc -raw -length 0 src.mp4       # Chromaprint，pip install pyacoustid
fpcalc -raw -length 0 short.mp4
# 2) 对指纹/chroma 做滑动互相关精修到帧级
```

流程：
1. 短片按镜头切分（PySceneDetect，`ContentDetector`）。
2. 每个短片镜头 → 在源音轨上滑窗互相关，取峰值得到 `src_start_t`。
3. **时间轴斜率检验**：拟合 `short_t → src_t`，斜率 ≠ 1 → 变速 → **整对丢弃**（斜率顺便就是变速检测器）。

**回退**：换 BGM / 纯音乐 / 静音 → 音频失效 → 退到视觉帧检索（帧级嵌入最近邻，如 CLIP/DINO 特征 + FAISS）。**先把有音轨的吃干净，性价比最高。**

产出：`short_frame → src_frame` 的逐帧映射，以及每镜头的对齐置信度。

---

## 5. 阶段 3：空间配准（3-DoF 约束，别用通用单应）

已知这是**轴对齐、定宽高比**的裁切 → 只有 3 个自由度 `(x, y, scale)`。**把模型约束死，外点少一个数量级。**

**搜索顺序**（从最常见、最便宜开始）：

```
1. 满高假设 (1-DoF)：h = src_h, y = 0, scale 固定 → 只搜 x
      覆盖大多数竖屏切片；1920x1080 源 + 9:16 → w=607, 只剩 x 未知
2. 失败 → 3-DoF：粗到细搜 (scale, x, y)
3. 再失败 → 丢弃这一对帧
```

**实现建议：从模板匹配起步，不要一上来上特征匹配。**

```python
# 尺度空间只有一维且窄，NCC 在重编码/轻度调色下够稳，实现远简单于 SuperPoint+LightGlue
import cv2
res = cv2.matchTemplate(src_frame_gray, short_frame_resized_gray, cv2.TM_CCOEFF_NORMED)
_, peak, _, loc = cv2.minMaxLoc(res)   # peak 本身就是置信度
```

- NCC 失败案例攒够了，再决定要不要升级到特征匹配。
- 若上特征匹配：`cv2.estimateAffinePartial2D` 拟合相似变换，**把「旋转角 ≈ 0」当有效性检验**——真裁切无旋转，估出旋转=匹配错了。
- **许可提醒** `[V]`：SuperPoint 权重历来非商用（Magic Leap），LightGlue 代码 Apache 但依赖的检测器要挑；permissive 替代用 DISK / ALIKED。

产出：逐帧 `[x, y, w]` + 逐帧配准置信度（NCC 峰值或内点率）。

---

## 6. 阶段 4：轨迹平滑 + 验证

单帧估计有野点。**真实裁切轨迹是平滑的**（人手 pan 或工具插值），每帧跳 200px 是估计失败，不是真实剪辑。

- 对逐帧 `x(t)`（及 `y, scale`）做鲁棒平滑：Kalman / Savitzky-Golay / 轨迹级 RANSAC。
- **平滑度做二次过滤**：残差超阈值的帧标为低置信，成片段超阈值 → 丢弃该镜头。
- 平滑度过滤比逐帧阈值可靠得多——它利用了「轨迹连续」这个强先验。

产出：清洗后的轨迹 + 每帧最终 `conf`。

---

## 7. 阶段 5：丢弃规则（决定标签质量，从头就统计）

**这个过滤器的质量 = 标签质量**，而「标签质量 vs 下游性能」曲线是论文里最难反驳的实验。**每条丢弃理由都要计数留档**（阶段 1 的失败分布直接来自这里）。

| 丢弃条件 | 检测方式 | 语义 |
|---|---|---|
| 音频时间轴斜率 ≠ 1 | §4 拟合斜率 | 变速/速度斜坡 |
| 估计 scale > 1 | §5 输出 | 短片比源更宽 → 配错了 |
| 估计宽高比 ≠ target | §5 输出 | 加了黑边 / 匹配失败 |
| 短片大面积文字/贴纸 | 文本检测（PaddleOCR/EAST） | **裁切位置可能在避让文字 → 另一个目标函数，污染标签** |
| 短片含源里没有的画面 | 阶段 2 检索置信度骤降 | 插入了 b-roll |
| NCC 峰值 / 内点率过低 | §5 输出 | 配准不可信 |
| 轨迹抖动超阈值 | §6 残差 | 逐帧估计失败 |
| 分屏 / 画中画 | 版式检测 | 非单窗裁切 |

> 阈值先给保守值宁缺毋滥，阶段 1 用人工核过的对来校准每个阈值的 precision。

---

## 8. 阶段 6：标签导出

- 按 §0 契约落 JSON，一对一文件。
- **同时导出可视化**（源帧上画裁切框 + 短片对应帧并排）供抽检——阶段 1 人工过对时用。
- 版本化：`extractor_version` 写进 provenance，改了抽取器能追溯哪批标签受影响。

## 9. 建模陷阱：未入选帧 ≠ 负样本（必须在数据层处理）

短片有时长上限 → 大量「其实不错但没被选中」的帧会被误标为负例 → 直接当二分类训会**系统性压低召回**。这是 **PU（positive-unlabeled）问题**。

**数据层对策**（也可写成一个贡献点）：
1. 未入选帧一律标 `unlabeled`，不标 `negative`（见 §0 `negatives_policy`）。
2. 训练用 PU 损失 / 先验校正，或**只在同一镜头内部**构造对比（入选帧 vs 同镜头未入选帧），避开跨镜头假负例。
3. **偏好对天然产出**：入选镜头 vs 未入选镜头 = 一对 → 直接喂 DPO（对上赛方 RL/偏好提示 + 论文立论，零新增标注）。

## 10. 质量控制：全程要盯的数

| 指标 | 在哪测 | 为什么关键 |
|---|---|---|
| 合成对轨迹恢复中位/尾部误差 | 阶段 0 | 标签置信度上界 |
| **yield rate**（候选对 → 可用标签的比例） | 阶段 1 | **决定 T1 生死的那个数，现在完全未知** `[V]` |
| 各丢弃理由占比 | 阶段 5 | 指导抽取器该修哪里 |
| 人工抽检 precision（每阈值） | 阶段 1 | 校准 §7 阈值 |
| 标签质量 vs 下游性能曲线 | 训练后 | 论文主结果（T1） |

> **阶段 1 的 yield rate 若只有个位数百分比，T1 成本会比预期高一个量级——必须在投稿前几个月知道，不是前两周。**

## 11. 合规与发布（不给法律结论，仅通行做法 `[V]`）

- 平台批量下载通常违反 ToS → **大概率不能再分发视频本体**。
- 领域标准做法：**只发布 URL + 时间戳 + 你导出的标注**，不发视频（HowTo100M、ActivityNet 皆如此）→ 这条路可发表。
- 比赛侧无论如何要披露来源、清洗方式、许可、用途 `[F]` → 披露表早建。
- T2/T3 许可通常更清晰 → 发布受阻时的退路。
- **待向组委会确认** `[V]`：用闭源 API 标注**自有训练数据**是否合规（赛规仅禁其用于**测试集推理** `[F]`，训练数据是另一回事，但需书面确认）。

## 12. 建议目录结构

```
data_pipeline/
├── configs/
│   ├── sources_t1.yaml         # 频道/账号清单、配对规则
│   └── thresholds.yaml         # §7 所有阈值集中管理，便于校准
├── stage0_synth/               # 合成对生成 + 评测（永久回归集）
├── stage2_temporal/            # 音频指纹 + 互相关 + 斜率检验
├── stage3_spatial/             # NCC / 特征匹配，3-DoF 约束搜索
├── stage4_trajectory/          # 平滑 + 野点过滤
├── stage5_filter/              # 丢弃规则 + 计数统计
├── stage6_export/              # JSON 契约 + 可视化
├── labels/                     # 产出（url-only，不含视频）
└── reports/                    # yield rate、误差、丢弃分布
```

`thresholds.yaml` 示例（起始值，待校准）：

```yaml
temporal:
  slope_tolerance: 0.02          # |slope - 1| 上限
  xcorr_min_peak: 0.4
spatial:
  ncc_min_peak: 0.55
  max_scale: 1.0                 # >1 直接丢
  ratio_tolerance: 0.03
  max_rotation_deg: 1.5
trajectory:
  max_jump_px_per_frame: 60
  smooth_residual_max: 25
filter:
  text_area_frac_max: 0.15
```

## 13. 里程碑与通过标准

| 阶段 | 做什么 | 通过标准 |
|---|---|---|
| **M0** | 合成对 + 抽取器 + 误差评测 | 已知轨迹恢复误差进入可接受区间；各退化下失败模式清楚 |
| **M1** | 1–2 个高产源取 50–100 对，逐对人工核 | 量出 yield rate 与失败原因分布 |
| **M2** | 用 M1 调好的过滤器放量 | 标签质量-规模曲线开始能画 |
| **M3** | 训练 + 规模曲线 + 标签噪声消融 | **= T1 论文主结果** |

## 附：与决策简报的挂钩

- 本 pipeline 服务 **T1（专业剪辑是可规模化取景监督源）**，是三 thesis 组装的脊柱。
- §9 的偏好对 → 语义分支 DPO 训练输入。
- §3 的 3-DoF 约束 → 对应几何分支「输出 x 方向分布 + 少量尺度」，非点估计。
- §10 的 yield rate、§0 的误差 → 决策简报 06 中「官方短片许可与可发布性」反转条件的量化输入。
- **未决前提**：GT 是稠密还是抽样标注 `[V]`——它决定几何分支逐帧还是逐段，也决定本 pipeline 导出是否要下采样对齐比赛标注粒度。
